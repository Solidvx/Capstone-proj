## 현행 과제에 병합한 보안 수행·인수 조건 — 보안 보강의 최종 재현

이 절은 2026-09-09 보안 상세 계획을 기존 단계에 반영한 실행 조건이다. 초기 보안 보강 절과 함께 적용하며 제품 실행 완료 기록은 아니다. 상세 규칙은 [메시지·상태 규약](../../../docs/development/security/인증이벤트_메시지_상태규약.md)과 [송신·큐·실패 정책](../../../docs/development/security/인증이벤트_메시지_상태규약.md#planning-final)을 참조한다.

**선행 조건:** ECU M5·IVI M5의 동결 설정과 실제 구현 증거, 공동 시험 원장을 인수한다. 새 calibration으로 기존 최종 평가 결과를 조용히 바꾸지 않는다.

**수행:** 동일 입력/설정으로 raw/IF·인증 진단 소비·공식 경보 결과를 재생성한다. 단절·새 epoch·같은 epoch 순번 초기화 시도·큐 포화·status 불일치·늦은 이벤트·종료를 재현하고 producer/receiver/consumer 원장을 대조한다.

### 3.2 Ablation 재실행과 재현성 검증

**REP-1=A 반영:** 각 방어 구성·공격 조합의 성공률 차이 `abs(current - previous) ≤ 5%p`를 적용한다. 이전 0%에도 같은 식을 사용한다. 원래 TC의 보안 성능 기준은 별도 적용하며 통계적 신뢰성 증명으로 해석하지 않는다. 누락·중복·빈 결과는 INVALID로 처리한다.

```bash
# 저장소 루트에서 실행
python -m security.experiments.verify_reproducibility \
  --previous results/m5-physical-001 --current results/m5-physical-002 \
  --output results/m5-repro.json
```

현재 비교기는 두 검증 행렬 폴더를 사용하며 같은 설정/도구/실제 입력/seed가 아니면 INVALID다. 원장 기반 명령·CSV는 [분석 안내](../../../docs/development/playbooks/experiment-analysis.md)를 따른다. 아래 pandas 코드는 역사적 CSV 비교 예제이며 현재 CLI/API가 아니다.

```python
#!/usr/bin/env python3
"""Ablation 재현성 검증 — 세트별 편차 <= 5%p."""
import argparse
import sys

import pandas as pd

parser = argparse.ArgumentParser()
parser.add_argument("--previous", default="results/ablation_summary_previous.csv")
parser.add_argument("--current", default="results/ablation_summary.csv")
parser.add_argument("--threshold", type=float, default=5.0)
args = parser.parse_args()

prev = pd.read_csv(args.previous)
curr = pd.read_csv(args.current)
expected = {(c, a) for c in (1, 2, 3)
            for a in ("spoofing", "replay", "flooding", "fuzzy")}
for frame in (prev, curr):
    if frame.duplicated(["config", "attack_type"]).any():
        raise ValueError("duplicate experiment combination")
    if set(zip(frame["config"], frame["attack_type"])) != expected:
        raise ValueError("missing or unexpected experiment combination")
    rates = pd.to_numeric(frame["success_rate"], errors="raise")
    if not rates.between(0, 100).all():
        raise ValueError("invalid percentage")
merged = prev.merge(curr, on=["config", "attack_type"],
                    suffixes=("_prev", "_curr"), validate="one_to_one")

print(f"{'Config':>6} {'Attack':>10} {'Prev%':>8} {'Curr%':>8} {'Diff%p':>8} {'Status':>7}")
print("-" * 52)

all_pass = True
for _, row in merged.iterrows():
    p, c = row["success_rate_prev"], row["success_rate_curr"]
    diff = abs(c - p)  # Inputs are percentages; difference is percentage points.
    status = "PASS" if diff <= args.threshold else "FAIL"
    all_pass &= status == "PASS"
    print(f"{row['config']:>6} {row['attack_type']:>10} {p:>8.1f} {c:>8.1f} {diff:>8.1f} {status:>7}")

print()
if all_pass:
    print(f"RESULT: ALL PASS — 모든 세트 편차 <= {args.threshold}%p")
else:
    print("RESULT: FAIL — 편차 초과 세트 있음. 원인 분석 필요")
    sys.exit(1)
```

```bash
# 현재 실행 명령은 위의 --previous/--current/--output을 사용한다.
```

> REP-1=A: 20%→24%는 4%p, 0%→4%도 4%p다. 상대 변화율을 계산하거나 기준값 0에 별도 예외식을 적용하지 않는다.

**편차 5%p 초과 시 확인 순서**

1. seed 배정이 시행마다 결정적인지 ([M5](M5_Ablation.md) 3.1)
2. CPU governor가 performance인지
3. `if_detector`의 `RANDOM_STATE=42`가 유지되는지
4. 버스에 외부 트래픽이 섞이지 않았는지
5. M5 이후 임계·특징을 바꿨는지 (바꿨다면 이전 결과와 비교 자체가 성립하지 않는다)

### 3.4 ICD 교차 검토

Node B 담당자와 함께 항목별로 확인한다. 불일치가 나오면 [00_협업_규약](../common/00_협업_규약.md)의 `interface-change` 게이트를 따른다.

- [ ] `0x100` SOC/SOH 스케일 `×0.5`, raw 0~200
- [ ] `0x100` Voltage/Current 빅엔디언
- [ ] Current는 int16 2의 보수 (양수=충전)
- [ ] Temperature offset `+40`, raw 상한 165
- [ ] 실행에 적용한 계약 버전을 기록하고 [ICD](../../../docs/ICD.md)와 대조한다. 기존 형식의 `0x100` byte 7은 Reserved=`0x00`, §8 승인 목표로 전환한 형식은 sensorState 정의와 값 인수 규칙을 검증한다. 전환 시 양측 구현·Python 참조·Mock·직렬화·시험의 동시 적용과 혼합 버전 방지를 확인한다.
- [ ] `0x101` State·Reason 코드를 [ICD](../../../docs/ICD.md) §1.3과 대조하며, `0x07`의 발생 조건·상태 전이·Node B 표시를 포함한다.
- [ ] `0x102`/`0x103` HMAC 입력 = `CAN_ID(2B BE) || Counter(4B BE) || Payload(8B)`
- [ ] 인증 프레임 = `TruncatedMAC(4B) || RollingCounter(4B BE)`
- [ ] 롤링 카운터 윈도우 규칙(delta 1~100)이 양측 동일
- [ ] `0x200` 레이아웃이 `>BBHI`와 동등 (AttackType, Score×0.01, SuspectCANID BE, Timestamp uint32 BE)
- [ ] Node B parser가 같은 프레임을 같은 값으로 해석
- [ ] SecOC 키 경로·퍼미션이 양 노드 동일 (`/etc/secoc/key.bin`, 400)

**대조 방법**: 같은 프레임 바이트열을 양측이 각자 디코드해 값을 비교한다. 표를 서로 낭독하는 방식은 오류를 놓친다.

## 5. 실패 시 대응과 우회

**재현성 편차 초과** — 3.2의 확인 순서를 따른다. 원인을 못 찾으면 편차 값과 조건을 그대로 보고한다.

**ICD 불일치 발견**
- 구현이 틀렸으면 구현을 ICD에 맞춘다
- ICD가 틀렸으면 `interface-change` PR로 ICD·SRS·양측 SDD·TEST_PLAN·구현·시험을 한 단위로 갱신한다
- 어느 쪽도 조용히 고치지 않는다

**TC-PERF 목표 미달**
- 측정 지점을 먼저 검증한다. 지점이 다르면 수치가 아니라 정의 문제다
- 실제 미달이면 병목(주기 루프 내 blocking I/O, 로그, 화면 갱신 주기)을 찾아 기록한다
- 목표 미달을 목표 변경으로 덮지 않는다

**하드웨어 미가용으로 TC-PERF 측정 불가**
- `vcan0` 기반 측정치를 별도 표로 남기고 **물리 CAN 미측정**을 명시한다
- 발표에서 vcan0 수치를 물리 CAN 수치로 말하지 않는다
