## 사용 방법

- 질문마다 있는 **입력표**의 `선택` 칸에 `A`·`B`·`C` 중 하나를 적는다. 보충할 조건은 `추가 조건`에 적는다. 선택지에 없는 답은 직접 서술해도 된다.
- **빈칸을 승인으로 해석하지 않는다.** 답이 없는 항목은 결정되지 않은 것으로 두고 그 항목의 작업을 시작하지 않는다.
- 답변을 받으면 결정은 [의사결정 기록](의사결정_기록.md)의 ID 색인에 병합하고 관련 계획·작업 기록(CHG)에 반영한다. 이 문서는 그때 "답변 완료"로 표시한다.
- 설명은 `근거`가 가리키는 파일과 작성 시점에 확인한 상태만 쓴다. 목표값과 실측값, 합성과 물리 결과를 구분한다.

## 용어


| 용어                 | 뜻                                                                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------------------------------- |
| Config 1 / 2 / 3   | 방어 구성. 1 = 무방어(SecOC OFF·IDS OFF), 2 = SecOC만, 3 = SecOC + IDS. IDS만 켠 구성은 없다                                       |
| 공식 4종              | Ablation 대상 공격: flooding, fuzzy, replay, spoofing. 4종 × 3구성 × 유효 100회 = 1,200                                       |
| masquerade         | 진짜 송신을 멈추고 같은 주기로 가짜 `0x100`을 보내는 은밀한 공격. 공식 4종에 들지 않는 참고 사례                                                        |
| 합성 / vcan / 물리     | 결과 등급. 합성 = 시뮬레이션 트래픽, vcan = 가상 CAN, 물리 = 두 RPi 실제 CAN. 서로 대체할 수 없다                                                |
| 시행 단위 / 윈도우 단위     | 탐지율 집계 방식. 시행 단위 = 공격 1회 중 탐지 이벤트가 1건이라도 있으면 탐지, 윈도우 단위 = 1초 창마다 판정                                                 |
| 규칙 베이스라인 / 실시간 IDS | 서로 다른 탐지기. 규칙 베이스라인 = 오프라인 z-score(`rule_baseline.py`, ROC 분석 대상), 실시간 IDS = `runtime_detector.py`(Config 3 판정에 사용) |

| 선택     | 방식                                          | 영향                                                                                 |

| A      | 축소하지 않는다. 100회를 못 채운 구성·공격은 `NOT_RUN`으로 둔다  | 기준은 지켜지지만 오늘 낼 수 있는 물리 정량이 적을 수 있다                                                 |

## EXQ-4. Config 3에 Isolation Forest까지 넣을까요?

FR-SEC-006과 [M4](../../../plan/detail/ecu/M4_IDS_공격_물리통합.md) §3.5는 **실시간 Isolation Forest(IF)를 필수**로 둔다. IF를 실행하지 못한(SKIPPED) 경우 IDS 전체 완료로 처리할 수 없다. 지금 Config 3은 실시간 IDS의 규칙만 쓴다. IF 모드는 별도 정상 JSONL(완료된 1초 창 최소 2개)로 학습해야 하고, 그 수집·변환 도구는 아직 없다.


| 선택            | 방식                    | 영향                                             |
| ------------- | --------------------- | ---------------------------------------------- |
| A (추천, 마감 고려) | 규칙으로 실험하고 IF는 후속으로 둔다 | 오늘 가능하다. IF 미실행을 문서에 명시하고 IDS 전체 완료로는 표시하지 않는다 |
| B             | 규칙과 IF를 모두 실행한다       | 공식 요구에 가깝다. 정상 데이터 수집·변환과 IF 학습이 추가되어 시간이 늘어난다 |
| C             | IF만 사용한다              | 규칙 결과는 참고로만 남긴다. 정상 학습 데이터가 반드시 필요하다           |


두 탐지기를 함께 보고할 때는 탐지기 비교 축과 방어 구성 축을 한 표에 섞지 않는다. 근거: M4 §3.5, [M5](../../../plan/detail/ecu/M5_Ablation.md) §2.

## EXQ-5. 공식 4종 밖의 masquerade 결과를 어떻게 다룰까요?

공식 4종은 규칙 베이스라인만으로 기준을 충족했다(합성, 위 상태표). masquerade는 양과 주기가 정상과 같아서 양을 보는 규칙은 놓치고(0%), 메시지별 약속(허용 ID·주기·값 고정)을 보는 사양기반(`security/ids/spec_detector.py`)은 잡는다(100%, 오탐 0%). 공식 실험 대상이 아니므로 다룰지 여부는 선택이다.


| 선택     | 방식                                                          | 영향                                                                                  |

## EXQ-11. Config 3 실시간 IDS의 임계를 어떻게 확정할까요?

Config 3의 탐지는 실시간 IDS(`runtime_detector.py`)의 규칙으로 판정했다. 그 임계(최소 주기 50ms, 300ms 누락, 초당 100프레임, 1초 내 실패 3회 등)는 탐지기 README가 "시험용 초기 정책이며 실차·실물 보정값이 아니다"라고 밝힌 기본값이다. [M5](../../../plan/detail/ecu/M5_Ablation.md) §3.4는 IDS 동작점을 정하고 **확정 임계를 SDD-ECU에 기록**하도록 요구한다. 위 ROC 결과는 다른 탐지기(규칙 베이스라인)의 것이라 이 임계의 근거가 되지 않는다. 정상 트래픽만 넣었을 때 이 탐지기의 오탐도 아직 재지 않았다.


| 선택            | 방식                                                            | 영향                                                          |
| ------------- | ------------------------------------------------------------- | ----------------------------------------------------------- |
| A (추천, 마감 고려) | 기본값을 그대로 확정값으로 쓰고, 정상 트래픽만 넣은 오탐(분모 100윈도우 이상)을 먼저 재서 함께 기록한다 | 오늘 가능하다. 저장소 작업은 제가 한다. 오탐이 5%를 넘으면 그대로 보고하고 B로 넘어갈지 다시 묻는다 |
| B             | 임계 선정용 정상·공격 데이터로 임계를 보정한 뒤 고정한다. 선정용과 평가용 데이터를 분리한다          | M5 절차에 가장 맞다. 보정·재실행 시간이 든다                                 |


두 안 모두 평가 데이터를 본 뒤 임계를 바꾸지 않는다. 근거: M5 §3.4·§3.5.1, `security/ids/README.md` 검사와 경보 절.
