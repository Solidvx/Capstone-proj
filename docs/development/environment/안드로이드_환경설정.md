# Android AOSP·HIDL HAL 환경 준비 및 질문

> **상태(2026-09-22)**: ADR-010으로 Android 포팅은 현 제출 범위에서 제외되었다. 이 문서는 과거 조사·후속 과제 자료이며 현재 구현은 [Qt Plan B](../../../plan/IVI_PLAN_B_전환계획.md)를 따른다.


문서 역할: 플랫폼 후보·사용자 환경 답변·서버 인계 절차다. 현재 후보와 인계는 [후보 검증](#android-candidate)·[서버 실행 인계](#android-handoff), 개발 설계는 [SDD-IVI](../../SDD-IVI.md), 착수 제한은 [종합 검토 관문](../reviews/문서_종합정합성_검토.md#execution-gates-current)을 따른다. 후보 선정과 실제 호환성 인수는 구분한다.

작성일: 2026-09-07

> **A-1~A-14 답변 접수 완료.** 2026-09-08 사용자 지시에 따라 서버에서 받아오는 작업은 사용자가 담당하며 현재 에이전트 작업에서 제외한다. 저장소 URL·연결 방식 추가 답변을 요구하지 않고 독립 실험을 진행한다. 서버 빌드·장비 검증 완료를 뜻하지 않는다.

현재 주 빌드 장비는 서버이며 Raspberry Vanilla Android 16은 우선 검증 후보다. A-1~A-14 답변은 접수 완료했고, 소스 revision·최종 호환성·빌드·장비 인수는 후속 실행으로 확인한다. 사용자는 Android AOSP·HIDL HAL 방식을 우선한다. 아래 과거 질문표의 빈칸은 새 답변 요청이나 전체 환경 미선정을 뜻하지 않는다.

빠른 이동: [일정 D1~D10과 마감](#android-schedule) · [후보 검증](#android-candidate) · [서버 실행 인계](#android-handoff). `일정 D1`은 계획 검토 문서의 `문서 검토 D1`과 별개다.

## 1. 목표와 현재 보유 장비

목표 경로는 `MCP2515 → SocketCAN → C++ HIDL HAL → Android Service → 대시보드 앱`이다. SecOC 검증과 상태 전달은 프로젝트 [ICD](../../ICD.md)의 현행 계약·승인 목표·세션 후보 전환 절차를 따른다. HIDL 구현을 Android Automotive 전체 플랫폼이나 표준 차량 VHAL 구현과 동일한 과제로 간주하지 않는다.

Node B 장비는 RPi4 Model B 8GB, SanDisk microSD 128GB, MCP2515/TJA1050 8MHz 모듈, 레벨 컨버터 2개, Touch Display 2, 5V 3A 어댑터와 듀얼 팬 케이스다. 상세 근거와 배선은 [의사결정 기록 Part 2 §1](../governance/의사결정_기록.md#hardware-inventory)을 따른다. 물리 CAN·Android 부팅·화면/터치·HAL 호환성은 아직 시험하지 않았다. 사용자가 보고한 SSH/vcan0 경험은 별도 Linux 개발 경험으로 기록한다.

HIDL은 공식 문서에서 deprecated로 표시된다. 곧바로 불가능하다는 뜻은 아니지만 특정 버전에서 프로젝트 HIDL을 빌드·등록·호출하는 증거가 필요하다. 최신 버전 또는 오래된 버전을 이름만으로 확정하지 않는다.

### 검토할 소스 후보와 역할

- **Raspberry Vanilla:** RPi4용 AOSP 소스 빌드 구성을 우선 조사할 후보. HIDL 서비스와 커널을 직접 추가할 수 있는 빌드 경로를 검토한다. 확인한 `android-15.0` 브랜치는 유지보수 종료 안내가 있으므로 자동 채택하지 않는다.
- **KonstaKANG AOSP 이미지:** 초기 보드·화면 동작 비교용 후보. 완성 이미지만 설치하는 것이 자체 HIDL 서비스의 소스 빌드·등록·배포를 해결하지는 않는다. 이미지와 공개 소스의 대응 및 사용 조건을 확인한다.
- **최종 선정 기준:** RPi4/Touch Display 2 지원, HIDL 빌드 가능성, 커널 CAN 수정 가능성, 재현 가능한 revision, 사용 가능한 빌드 장비와 일정. 버전·manifest commit은 검토 후 고정한다.

참고 근거: [AOSP 개발 환경 요구사항](https://source.android.com/docs/setup/start/requirements), [HIDL 공식 문서](https://source.android.com/docs/core/architecture/hidl), [Raspberry Vanilla Android 15 브랜치](https://github.com/raspberry-vanilla/android_local_manifest/tree/android-15.0), [KonstaKANG RPi4 AOSP 15 안내](https://konstakang.com/devices/rpi4/AOSP15/). 웹 문서는 변경될 수 있으므로 실제 선정 시 다시 확인한다. 위 RAM 권장은 계획용 판단이며 모든 버전의 공통 최소 사양을 뜻하지 않는다.

## 4. 소스 선정 후 채울 항목 — 지금 몰라도 됨



### A-1~A-8 답변 검토 (2026-09-08)

답변 접수 완료. 개인 PC는 Windows 11 Home, i7-1360P, RAM 16GB LPDDR5, SSD 여유 약 135GB다. 기존 Windows 유지가 필수이며 WSL·가상머신은 있으나 버전과 할당 자원은 미확인이다. 사용자는 개인 PC 활용을 선호하고 부족하면 서버 PC를 사용할 수 있다고 확인했다. A-8에 따라 사용자 정의 HIDL HAL → Android 서비스 → 대시보드 앱을 대상으로 하며 표준 VHAL·CarService는 요구 범위에 포함하지 않는다.

**검토 결론:** 개인 PC는 편집·앱 개발·ADB·로그 수집에 활용하고, AOSP 전체 이미지와 HIDL 서비스의 플랫폼 빌드는 서버에서 수행하는 구성을 권고한다. 서버 사양 확인 전 최종 배치는 미정이다. 현재 [AOSP 공식 요구사항](https://source.android.com/docs/setup/start/requirements)은 최신 릴리스 전체 빌드에 x86-64 Linux, RAM 최소 64GB, 여유 저장공간 최소 400GB를 제시한다(2026-09-08 확인). 개인 PC의 135GB는 이 저장공간 기준에 미달하며 WSL·가상머신을 사용해도 물리 RAM·디스크 부족이 해소되지 않는다. 선택할 이전 Android 버전의 실제 요구량은 별도 확인하되 16GB 환경의 저병렬·스왑 빌드를 9일 일정의 주 경로로 확정하지 않는다.

A-6 원문은 **“9일 안에 완성해야 한다.”**이다. 기존 질문은 첫 부팅·최소 HAL 시연을 물었으므로 전체 프로젝트 완성 기한으로 확대 해석하지 않는다. 아래에서 정확한 범위를 확인한다. 기존 M1~M8 주차표를 9일 일정으로 완료 가능하다고 간주하지 않는다.

### A-9~A-11 답변 반영 및 실행안 (2026-09-08)

A-9~A-11 답변 접수 완료. 서버 CPU·RAM·SSD는 사용자 설명상 고사양이며 여유가 있으나 수치·운영체제는 미확인이다. 내부망에서 직접 연결 가능하고 언제든 접근할 수 있다. 설치 권한·외부 소스 다운로드·장시간 작업 및 파일 보관 조건은 답변에서 확인되지 않았다. 내부망 접근 가능을 인터넷 다운로드 가능으로 해석하지 않는다.

최신 기한은 **SecOC·IDS를 포함한 전체 시연을 10일 이내 완료**하는 것이다. 앞선 9일/최소 HAL 기준보다 이 답변을 우선한다. 절대 마감일은 미제공이므로 날짜를 임의 확정하지 않는다. 아래 D1~D10은 실제 착수일부터의 작업 배분안이며 달성 보장이 아니다. 기존 M1~M8을 모두 완료했다는 의미도 아니다.

**조건부 환경안:** 서버를 AOSP·커널·HIDL 플랫폼 빌드의 주 장비로 사용하고 개인 Windows PC를 코드 편집·앱 개발·장비 연결에 사용한다. Linux 환경·자원·도구 설치·다운로드 가능 여부를 확인한 뒤 소스 다운로드에 착수한다. 원격 접속 주소나 자격 증명은 문서에 남기지 않는다.

### A-12~A-13 최종 반영 (2026-09-08)

사용자는 서버 성능에 의구심을 가질 필요가 없다고 명시했다. **서버 자원은 충분하다는 사용자 확인을 계획의 전제로 채택하고 사양 재질문을 종료한다.** 서버를 AOSP·커널·HIDL 플랫폼의 주 빌드 장비로, 개인 Windows PC를 편집·앱 개발·장비 연결용으로 배치한다. 구체적인 CPU·RAM·SSD 수치를 추정해 기입하지 않는다.

A-12는 현재 확인이 어렵다는 답변으로 접수 종료한다. 운영체제·도구 설치·다운로드 조건은 확인된 사실로 만들지 않고 실제 서버 착수 시 담당자가 환경에 맞는 명령을 선택하기 위한 점검으로 이관한다. 이 점검을 이유로 문서 검토·소스 후보 조사를 보류하거나 같은 사양 질문을 다시 하지 않는다. 실행에서 실제 제약이 발견되면 그 제약과 필요한 조치를 보고한다.

전체 시연 마감은 **2026-09-18**로 반영한다(현재 연도 기준, 시각 미지정). 9월 8일은 준비·계획 정리일, D1~D10은 9월 9~18일로 배치한다. D1=9/9, D2~D3=9/10~11, D4~D5=9/12~13, D6~D7=9/14~15, D8~D9=9/16~17, D10=9/18이다. 실제 착수가 늦어져도 마감일을 자동 연장하지 않는다. 위의 상대 일정·미제공 마감·서버 확인 대기 설명은 이 최신 결정으로 대체한다.

**인터뷰 상태:** A-1~A-13 접수 완료, 현재 추가 사용자 답변 요청 없음. 다음 작업은 소스 후보의 RPi4·HIDL·CAN·Touch Display 2 지원 대조와 Android 독립 문서 정합성 개선이다. 소스 revision·lunch target은 조사 후 선정하며 서버 접속·설치·빌드 및 실장비 시험은 아직 수행하지 않았다.

## 5. 수행 순서와 완료 판단

현재 A-1~A-13 인터뷰는 종료됐다. 아래 1번의 자원 확인은 사용자에게 사양을 다시 요청하는 절차가 아니라 담당자의 실제 서버 착수 점검이다.

1. A-1~A-8을 확인하고 빌드 PC/서버와 소스 후보를 비교한다.
2. 소스 revision과 RPi4 지원을 확인하고 최소 이미지 빌드·부팅·ADB를 검증한다.
3. 최소 HIDL 서비스의 생성·등록·호출을 검증한다. 이 단계가 안 되면 해당 버전 채택을 완료로 표시하지 않는다.
4. MCP2515 실제 송수신, 서비스 권한, DSI·터치를 확인한다.
5. 프로젝트 SecOC·HAL·Service·앱을 연결하고 공식 시험으로 인수한다.

표시·부팅 성공, HIDL 통신 성공, CAN 수신 성공은 각각 별도의 증거다. 모든 단계의 로그·설정·이미지/소스 버전을 남기며 실측하지 않은 수치로 완료를 판단하지 않는다.

### 소스 고정과 실행 인계

1. IVI 담당자가 서버 Linux 환경·설치/다운로드 조건을 실제 착수 시 확인한다. 확인 불가 값을 문서에 추정 입력하지 않는다.
2. 위 후보의 AOSP tag, local manifest commit, 각 프로젝트 commit, 커널 소스와 사용한 커널 산출물의 대응을 기록한다. 브랜치 이름만 기록한 상태는 재현성 고정 완료가 아니다.

### 서버에서 실행할 후보 준비 순서

서버의 Linux 셸에서 전용 작업 디렉토리를 선택한 뒤 실행한다. 현재 PC의 135GB 여유 디스크에 AOSP를 내려받지 않는다. 아래는 서버용 인계 명령이며 이 세션에서 실행하지 않았다. 기존 소스 트리가 있는 디렉토리에 새 manifest를 덮어쓰지 않는다. OS별 도구 설치 명령은 실제 서버 환경에서 선택한다.

```bash
# git, repo, curl 및 AOSP 빌드 의존성이 준비된 서버의 새 빈 디렉토리
repo init -u https://android.googlesource.com/platform/manifest -b android-16.0.0_r4
mkdir -p .repo/local_manifests
curl --fail --location https://raw.githubusercontent.com/raspberry-vanilla/android_local_manifest/fdb000589e7655748be4baf3787c7bb66f8f81f9/manifest_brcm_rpi.xml -o .repo/local_manifests/manifest_brcm_rpi.xml
repo sync
# 아래 출력 파일은 동일 이름의 이전 증거가 없는 새 증거 디렉토리에 보존
repo manifest -r -o resolved-manifest.xml
. build/envsetup.sh
lunch aosp_rpi4-bp4a-userdebug
make bootimage systemimage vendorimage -j"$(nproc)"
./rpi4-mkimg.sh
```

명령별 종료 코드·로그를 확인하며 실패 뒤 다음 단계로 넘어가지 않는다. 위 순서는 기본 후보 이미지를 준비하는 절차다. 프로젝트 HAL·init·VINTF·서비스/프레임워크 연결을 아직 포함하지 않으므로 기본 이미지 생성만으로 HAL 과제를 닫지 않는다. 생성 이미지 경로는 실제 빌드 출력에서 확인해 hash와 연결하고, SD 기록 대상 장치는 실제 장비를 확인한 후 정한다.

MCP2515에 필요한 커널 설정이 없으면 [Android 16 커널 빌드 절차](https://github.com/raspberry-vanilla/android_kernel_manifest/tree/android-16.0)의 별도 트리에서 `common-android16-6.12-lts`와 고정 local manifest를 사용한다. 문서의 RPi4 대상은 `tools/bazel build --config=fast --config=stamp //common:rpi4`다. Image·DTB·overlay를 Android 트리에 반영할 때 소스 commit·config·산출물 hash의 대응을 기록한다. 타 버전 Image만 교체하거나 모듈 ABI·장치 트리를 생략하지 않는다.

현재 이 세션에는 해당 내부망 서버 터미널이 연결되지 않았다. 실제 서버 실행이 가능해지면 OS/도구 확인→동기화→기본 빌드→HAL 추가 검증을 이어간다. 서버 성능 재확인은 요구하지 않는다.
