# 운영 지침·도구 검증 시나리오

[구조 개선안](../../../프로젝트구조개선.md) §15의 WF 묶음을 유지한다. 원본의 개별 WF 정의를 새로 추정하지 않는다. 아래는 묶음별 후속 사례이며 공식 제품 TC를 대체하지 않는다.

| WF | 입력·실행 사례 | 기대 결과 |
|---|---|---|
| WF-01, 02, 14 | 프로젝트 작업 시작, IVI 준비 확인 | 루트 지침·해당 플레이북·실제 파일을 확인; 계획을 구현으로 오인하지 않음 |
| WF-03, 04 | 작은 수정과 다단계 제품 작업 | 기록 크기를 선택하고 관련 제품 시험을 연결 |
| WF-05, 06 | ICD 영향 변경 또는 파일 저장 | 기존 계약 변경 게이트 유지; 저장을 승인·구현 요청으로 해석하지 않음 |
| WF-07, 08, 13 | 새 참조·ID·소스 경로와 지침 탐색 | 실제 경로·확장자·공식 ID 확인; 고유 지침과 원본 관계 보존 |
| WF-09, 10 | 검사 실패·미실행 또는 검증 후 대상 수정 | 실패와 미실행 구분; 변경된 대상을 옛 증거로 통과 처리하지 않음 |
| WF-11, 12 | 후속 MCP 장애·중복 이벤트·동시 쓰기·경로 이탈 | CLI 또는 수동 대체, 허용 범위·충돌 검사; 미구현 기능은 not_run |
| WF-15, 16 | 도구·실행 방식 전환 후 작업 재개 | 같은 상태 원본·대상 해시·증거로 남은 일을 재구성 |

실행 시 사례별 대상 파일·해시와 도구·버전을 고정하고, 입력을 재현한 뒤 기대 결과와 실제 결과를 비교한다. 명령·출력·참조 경로를 [증거 양식](../templates/evidence.md)에 남긴다. 판정은 pass/fail/not_run/not_applicable로 구분하며 제외 이유를 작성한다.

구조 단계에서는 문서 탐색·원본 연결·배치·내용 보존을 정적으로 확인한다. 실제 skill 로딩, CLI/MCP 실행, hook 발동·동시성은 후속 구현 환경에서 수행한다. 이번 정적 검사로 WF 전체를 통과 처리하지 않는다. [구조 검사 결과](../../aidlc/structure/verification.md)를 참조한다.
