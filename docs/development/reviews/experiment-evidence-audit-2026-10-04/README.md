# 실험 증거·문서 정합성 감사 — 2026-10-04

> 이 문서는 보완 전 감사 스냅샷이다. 후속 수정·검증 및 남은 측정 한계는 [보완 결과](REMEDIATION.md)를 따른다.


## 판정

등록된 실험 원본은 두 독립 보존 디렉토리에 보존되어 있고 무결성 검사에 통과했다. 그러나 **모든 실험 과정의 기록이 완전하고 모든 연관 문서가 최신이며 논문용 최종 결과까지 완성됐다는 판정은 불가**하다. 문서의 현재 상태 표기, 공식 표본 기준, 재개 실행 집계 도구, 분석 재현성에 보완이 필요하다.

이번 작업은 검토다. 기존 실험 원본·코드·계약·시험 기준은 수정하지 않고 이 감사 산출물만 추가했다. 실제 장비 재시험은 하지 않았다. 대상 브랜치는 `feat/security-live-validation`이며 기존 dirty worktree를 보존했다.

## 범위와 검증

- [통합·예비·진단 증거](../../experiments/ecu-ivi-integration-2026-10-03_04/README.md): inventory 534개 파일.
- [공식 Ablation 증거](../../experiments/physical-ablation-formal-2026-10-04/README.md): inventory 1,717개 파일.
- 합계 **2,251개 등록 파일**: 존재·보존 SHA256 검사 통과, 누락 0, 보존 해시 불일치 0, inventory 경로 중복 0, raw의 미등록 파일 0.
- IVI 전달 폴더의 현재 파일 **42개 모두** 원본 해시가 보존 inventory에서 확인됐다. 마지막 22H37M 전달까지 포함한 현재 로컬 폴더 기준이다.
- 공식 실행 원장 16개와 각 manifest의 `files_sha256` 검사를 통과했다.
- 실험 문서 및 CHG-014의 상대 파일 링크 검사에서 끊어진 경로 0. Markdown 앵커·외부 URL·전체 저장소 링크의 전수 검증을 뜻하지 않는다.
- 통합 증거의 파생 보고서/도구 7개는 최초 `sha256`와 다르지만 기록된 `preserved_sha256`와 일치한다. 목록은 [검사 결과](record-audit.json)의 `modified_preserved`에 있다. 원본 CAN 로그 변조로 판정하지 않는다.

검사 재현: 저장소 루트에서 `python docs/development/reviews/experiment-evidence-audit-2026-10-04/audit_records.py`, 이어서 같은 경로의 `audit_coverage.py`를 실행한다. `tmp` 디렉토리가 있어야 하며 결과는 `tmp/record-audit.json`에 생성된다. 이 폴더의 JSON은 감사 시점 스냅샷이다.

해시 일치는 현재 inventory 대비 무결성 증거다. 수집하지 않은 로그의 존재, 외부 백업, 서명된 생성 시점, 저장소 커밋/원격 보존까지 보증하지 않는다.

## 케이스별 보존 현황

아래 VALID/INVALID는 **실행기 원장 값**이며 논문 채택 여부나 제품 방어 PASS 판정이 아니다. 모든 행에 ECU·IVI 원본과 케이스별 분석/보고서가 있다.

| 구성 | 공격 | 보존 시도 수 | VALID | INVALID | 주요 해석 제한 |
|---|---|---:|---:|---:|---|
| C1 | flooding | 101 | 99 | 2 | 001~003 재개, trial 7 중복 보존 |
| C1 | fuzzy | 100 | 100 | 0 | 무인증 경보 입력과 실제 IDS 탐지를 구분 |
| C1 | replay | 100 | 100 | 0 | 수신·게시와 공격 성공 정의를 연결 |
| C1 | spoofing | 100 | 100 | 0 | IVI 원본 대조에서 주입 프레임 1개 차이·오류 증가 기록 |
| C2 | flooding | 100 | 100 | 0 | qdisc·재시도와 정상 BMS 전달을 별도 집계 |
| C2 | fuzzy | 100 | 100 | 0 | 주입된 0x200의 경보 게시 2건은 실제 IDS 탐지가 아님 |
| C2 | replay | 100 | 100 | 0 | 주입 데이터 게시와 새 정상 인증 프레임 결합을 구분 |
| C2 | spoofing | 100 | 100 | 0 | MAC_FAIL과 정상 게시 데이터 출처 대조 결과 사용 |
| C3 | flooding | 100 | 98 | 2 | trial 3·77 INVALID, v7/v8 변경, 구버전 계측 왜곡 |
| C3 | fuzzy | 100 | 100 | 0 | IDS 송신 0x200과 fuzzy 주입 0x200 분리 필요 |
| C3 | replay | 100 | 100 | 0 | 재전송 데이터·새 인증 결합과 IDS 경보 분리 |
| C3 | spoofing | 100 | 100 | 0 | IVI 주입 프레임 2개 차이·오류 증가, Qt 경고 21회 |
| 합계 | 12조건 | **1,201** | **1,197** | **4** | 계획 번호 1,200개 + 재시도 중복 1개 |

폴더 분리는 논리적으로 가능하다. 다만 C1 flooding 002/003 ECU 묶음과 C3 flooding 001~003 묶음은 상위 압축/컨테이너를 공유하고 내부 run 디렉토리로 구분한다. C1 flooding 002/003 보고서는 통합 보고서다. 따라서 모든 시도가 동일한 단일 폴더 템플릿이라는 의미는 아니다. 원본을 재배치할 필요 없이 최종 인덱스에서 run과 케이스를 명확히 연결하면 된다.

정상 통신, 성능 예비/공식, ADC 노브, vcan/물리 pilot, IF 학습·보정·독립 평가, SPI/큐/부하 진단도 첫 번째 증거 디렉토리의 개별 raw·보고서에 보존돼 있다. **대화에 등장한 모든 중간 명령 출력과 실패한 캡처의 원본까지 전수 보존됐다고 확대 해석할 수는 없다.** 일부 화면·정확한 프로세스 시각·시험 전 통계는 애초 미수집으로 기록돼 있다.

## 발견 사항과 보완 우선순위

### 높음 — 현재 상태 문서가 서로 다름

- [CHG-014 상태](../../../aidlc/changes/CHG-014/aidlc-state.md) 상단의 ‘최신 공식실행 상태’가 C1 flooding 초반 상태를 가리킨다.
- 공식 실험 README 상단은 아직 ‘다른 구성·공격 공식 시행은 미완료’라고 한다.
- 통합 실험 README에는 ‘공식 물리 Ablation 1,200회는 아직 시작하지 않았다’가 남아 있다.

후단의 누적 기록에 최신 결과가 있어도 현재 상태 문구의 충돌은 해소되지 않는다. 현황 요약을 하나로 정리하고 과거 기록에 당시 시점임을 명시해야 한다. 따라서 이전의 ‘관련 문서가 모두 적절히 최신화됐다’는 안내는 정정한다.

### 높음 — 공식 표본 기준과 실제 수집 정책 불일치

[TEST_PLAN](../../../TEST_PLAN.md)의 집계 해석은 4종×3구성×100개 **유효 공격 시행**이다. 실제 사용자 지시는 오류도 보존하며 계획 100회 시도를 수집하는 방식으로 변경됐다. 사용자의 변경 지시를 운영에 반영한 것은 맞지만, 기준 변경/편차와 논문 분모를 문서에 명시해야 한다.

현재 1,200개 계획 번호를 채웠다는 사실과 1,200개 유효 시행을 확보했다는 주장은 다르다. INVALID를 성공/실패 중 하나로 임의 치환하거나 제거해 100개 유효인 것처럼 표기하지 않는다. 추가 재시험은 이 감사만으로 요구하지 않는다.

### 높음 — 공용 집계 도구가 실제 재개 원장을 처리하지 못함

[summarize_live.py](../../../../security/experiments/summarize_live.py)는 trial 번호 상한을 `trials_per_attack`으로 검사한다. C3 flooding 003의 trial 78~100, 시행 개수 23 조합에 대해 직접 읽기 전용 실행한 결과 **`ValueError: invalid trial identity`**를 재현했다.

또한 run ID별 그룹과 유효 100개 기준을 사용하므로 현재의 케이스별 run ID, 이전 실행 연결, 버전 변경, 중복 trial 처리와 맞지 않는다. 도구 수정 시 원장은 그대로 두고 논리 케이스/시도/재시도/버전 구분과 분모 정책을 테스트해야 한다.

### 높음 — 논문 결과의 비교 가능성과 계측 한계

- C3 flooding은 도중 v7/v8 코드 변경이 있다. 특히 002의 일부 `delivery_ratio > 1`은 그대로 전달률로 쓰면 안 된다. 구버전 계측 구간 문제와 수정 후 자료를 구분하고 재계산 가능 여부를 표시해야 한다.
- 실행기 VALID와 외부 대조 이상은 별개다. C1/C3 spoofing의 수신 차이와 CAN 오류 증가도 결과에 남겨야 한다.
- 인증 성공 게시가 모두 정상 송신에서 왔다고 단정할 수 없다. replay의 동일 데이터·새 인증 프레임 결합은 오래된 인증 프레임 재수락과 다른 현상이다.
- IDS 탐지, IVI 경보 도착, 경보 분류 정확도, 화면 표시는 서로 다른 지표다. fuzzy 주입 0x200은 실제 IDS 경보와 분리한다.
- rules+IF 구성 사용만으로 IF의 추가 기여가 입증되지는 않는다. rule/IF 이벤트와 독립 정상 FPR 근거를 따로 제시한다.
- T4는 Qt frameSwapped 기준이며 물리 픽셀 시각이 아니다. Qt 경고와 화면 미수집으로 화면 무영향을 주장할 수 없다.

### 중간 — 재현 가능한 분석 도구와 최종 결과 묶음 부족

공식 증거의 `tools`에는 감사 시점 5개 스크립트가 있지만 다른 대조·집계 스크립트 상당수는 `tmp`에만 있다. 일부 경로·run ID가 고정되어 있다. 케이스별 보고서는 있어도 12조건을 동일한 정의로 집계하는 최종 재현 파이프라인 및 논문 표/그림 묶음은 완성됐다고 볼 수 없다.

사용한 분석기·버전·입력 해시·실행 명령을 정식 위치로 보존하고, 하나의 명령 또는 명확한 순서로 최종 표를 재생성할 수 있게 해야 한다. raw와 derived를 분리하고 출처 불명 자료는 최종 수치에 섞지 않는다.

### 중간 — 요구·시험·증거 연결과 운영 문서 동기화

[실행 플레이북](../../playbooks/live-security-validation.md)에 같은 run ID, INVALID 시 중단, 유효 100개 기준 등 이전 절차가 남아 있다. 변경 이력 추가만으로 본문 절차 충돌이 해결되지 않는다. 최신 CLI 정책과 정리해야 한다.

최종 TC/요구사항별로 근거 run, 분석 파일, 판정, 예외를 연결하는 매트릭스가 필요하다. SRS/SDD/계획 전체를 실험 일지로 바꿀 필요는 없으며 계약 변경 없는 ICD 수정도 불필요하다. 다만 현재 구현·운영 상태와 실제로 충돌하는 계획형 서술은 선별 수정해야 한다.

### 중간 — 장기 보존 확인 필요

원본은 로컬 독립 경로에 있지만 raw는 Git ignore 대상이고 현재 미커밋/미추적 변경이 있다. 이 검토는 원격/외장 백업을 검증하지 않았다. 대형 raw를 무조건 Git에 넣기보다 별도 원본 백업과 해시 목록, 문서/분석 코드의 버전 고정을 확인해야 한다.

## 권장 마무리 순서

1. 현재 상태 요약과 표본 정책/편차를 확정하고 관련 상태·플레이북·시험 추적 문서를 동기화한다.
2. 재개·중복·INVALID·코드 버전을 처리하는 집계와 재현 도구를 보완한다.
3. 기존 원본으로 12조건 최종 표, 지연/정상 전달/경보 출처/오류 부록을 만든다. 재계산 불가능한 항목은 미확인으로 남긴다.
4. 논문 산출물과 원본 백업을 검증한다. 실제로 필요한 추가 측정이 드러난 경우에만 그 범위를 별도 결정한다.

**현재 결론: 원본 보존 양호, 케이스 분리 양호, 문서 정합성 미완료, 논문 최종 집계·재현성 보완 필요.**
