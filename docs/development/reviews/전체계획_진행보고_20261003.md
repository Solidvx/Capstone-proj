## 결론

현재 작업의 중심은 **ECU M4 물리 보안 통합 / IVI P5 Pi 인수**다. ECU·IVI 핵심 구현과 실험 도구의 로컬 검증은 상당 부분 진행됐지만, **M3 미완성 워치독·커버리지 관문이 남아 있어 M1~M4 전체 완료라고 선언할 수 없다.** M5~M7은 도구·파일럿을 미리 준비한 상태이며 공식 실험·품질·최종 인수를 닫은 상태가 아니다. 근거 없는 전체 진척률(%)은 산정하지 않는다.

사용자는 루트 [임시_할일.md](../../../임시_할일.md)의 **003 전달본 1~4번을 완료했다**. ECU16/16, IVI11/11(SocketCAN 시험 제외), Python63+9 subtests 및 checksum OK를 보고했다. 실제 정상 통신 로그도 반환됐으며 다음 사용자 시험은 **IT-002**다. 로컬 후속 변경·최신 develop 통합은 별도 PR 기준선이며 기존003 archive는 변경하지 않았다. 지금 다시 복사하거나 Pi 시험을 중단할 필요 없다.

### 실제 정상 통신 결과 — NORMAL-PHYSICAL-002

반환한 IVI `can.log`와 `receiver.jsonl`을 대조했다. wire100/102 각각542개가 receiver 앞부분과 정확히 일치하고 인증된 SOC가 원본 payload와 일치한다. 541개 간격 평균100.074035ms, 최소96.201ms/최대100.254ms, 90~110ms 밖0개. counter0→541 연속. 전체 receiver에는 인증 게시1,767건, 실패 기록0건. CAN 전/후 RX errors8→8, dropped0→0, bus-off0→0. CAN 캡처 실제 프레임 구간 약54.14초, receiver 약176.74초로 수명이 달라 전체 개수는 같지 않다. 화면 LIVE/NORMAL은 사용자 확인이며 사진/픽셀 지연 실측은 아니다.

정상 경로 확인이지 물리 IT 전체·SOC 정확도·공격 차단·IDS 정상FPR의 완료 판정은 아니다. 원시 로그는 tmp에 보존하고 PR에는 넣지 않는다. IT-002는 현재 결과 대기이며 Pass로 표시하지 않는다.

## 남은 소프트웨어 작업 — 하드웨어 결과 대기와 별개

1. **워치독 M3**: 현재 main의 timeout callback은 로그만 남긴다. 작업 재시작의 소유권·종료/join·성공 판정·3회 연속 실패 집계·reason0x07 전이를 구현하고 TC-BSW-006~007로 검증해야 한다. timeout3회와 재시작실패3회를 혼동하면 안 된다. ADC worker·송신 counter 연속성을 보존해야 하므로 임의 detach/restart로 메우지 않는다.
2. **커버리지 M3/M6**: main/SocketCAN/I2C 등 미실행 경로에 적절한 통합 또는 대역 시험 필요. Fail-safe의 남은 2개 계측 분기는 private 동일 상태 전이 방어와 callback 예외 경로다. 공개 API로 도달하지 않는 경로를 숨기거나 private 접근을 뚫어 100%로 꾸미지 않고 계약/테스트 가능성 검토 후 처리한다.
3. **정적 분석/CI M6**: 로컬 VM에 cppcheck/lcov/gcovr가 없어 cppcheck NOT_RUN. GCC gcov JSON으로 측정은 가능했지만 Codecov/자동 게이트와 동일하지 않다. workflow·고정 ARM64 빌드 환경·정적 분석 실패 전파·자동 health/rollback 구현/검증이 남는다. 원격 secrets·브랜치 보호·실제 배포 변경은 별도 권한 필요.
4. **그래프/추적성 M6**: 기존 ROC SVG 외에 성공률·탐지율·지연 Ablation3종 및 EKF 오차 그림의 생성/검증, 요구사항별 공식 TC 결과 기록을 완성해야 한다. 수치가 없는 그림은 공식 실측으로 채우지 않는다.
5. **계약 관문**: sensorState wire·새 SecOC 세션 상세·IF 미분류 진단 wire 승격은 현행 승인 범위를 넘어서는 공동 변경이다. 기존 결정 질문을 다시 열지 않고, 필요할 때 별도 영향 분석·양측 합의로 진행한다.
