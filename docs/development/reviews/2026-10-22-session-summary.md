# 2026-10-22 이번 세션 전체 작업 총정리

이 문서는 이번 대화에서 확인·수정·실행한 작업과 인수인계 상태를 요약한다.
실험 조건·분모·정량 결과의 상세 원문은 [실험 총정리](../experiments/2026-10-22-experiments-summary.md)다.
사용자 터미널 출력, 사용자 화면 관찰, PC 수집 로그, 코드 검증을 구분한다. 실제 키·주소는 기재하지 않는다.

## 1. 목표와 역할

3노드 CAN에서 Pi3가 공격을 주입하고 ECU IDS의 탐지 유형이 IVI에 동일하게 전달·표시되는지 확인했다.
PC가 SSH로 실험 실행·종료·로그 수집을 제어한다. Pi3는 CAN 공격만 수행하며 SecOC 키가 없다.
ECU는 ADS1115 입력과 정상 CAN 송신, C3에서 IDS를 담당한다. IVI는 SecOC 검증·서비스 게시·화면을 담당한다.

앞선 구성 작업에서 공격 노드를 분리하고 CAN 연결·종단·속도 설정, PC SSH 관리 경로를 준비했다.
이전 Pi3 관리용 SSH 키는 선별 삭제했고 PC 전용 키의 공개키만 장비에 등록했다.
이번 작업에서는 이를 전제로 실행 실패를 진단하고 실험·화면·오탐·인증 거부를 검증했다.

## 3. 코드 변경의 핵심

- `can_attack_worker.py`: 기존 mixed-v1 보존, isolated-v1 분리 주입 지원. replay raw/auth 연속 송신.
- `runtime_detector.py`: 1초 내 서로 다른 미등록 ID3개 이상을 fuzzy 증거로 사용. UNKNOWN_ID/짧은 주기 자체는 이상 기록으로 유지한다.
- `pc_campaign.py`: 공격자가 주입한 경보 ID의 오인 방지, 분리 프로파일/IDS 버전 확인.
- `live_three_node_test360.py`: 재시도 소진 후 조건부 다음 조합 진행과 PARTIAL/재개 지원.
- `inspect_ivi_rejections.py`: 기존 로그의 거부 후보를 분석하되 귀속 불명확 사례의 차단율을 추정하지 않음.
- `mac_rejection_probe.py`, `score_mac_probe.py`, `pc_mac_check.py`: 키 없는 변조 인증30회와 IVI payload/source_data 대조.
- 관련 회귀 시험과 실행·인수인계 문서 추가.

CAN ID·DLC·SecOC 계약을 바꾸지 않았다. IDS에 실험 정답이나 공격 이름을 입력하지 않는다.
주입 조건과 탐지 규칙을 함께 바꿨으므로 이전 대비 순수 탐지 성능 개선으로 해석하지 않는다.
마지막 집중 검증은 관련31개 통과이며, 이전 확대 검증75개 통과/1Linux전용생략 기록도 있다.
이 숫자를 합산해 서로 다른 테스트 전체 통과 수로 표현하지 않는다.

## 4. 결과 한눈에 보기

| 측정/확인 | 결과 |
|---|---|
| 360회 수집 | 360/360 유효, 무효0, 추가 재시도0, 실행 세션12 |
| C3 유형 | 네 공격 각각30/30 ECU IDS·IVI 서비스 MATCH |
| 실제 화면 | 네 공격 문구와 가변저항 값 반영: 사용자 수동 확인 |
| 고정 정상 오탐 | 규칙0/298(0%), 규칙+IF2/298(약0.67%), PASS |
| 조작 정상 오탐 | 두 방식0/298(0%), PASS |
| replay 단일 주입 | auth16개 송신과 동일 payload 거부16건 일치: counter11/orphan5 |
| 변조 인증 단일 주입 | 연결 원본 일치, MAC_FAIL1건 |
| 반복 MAC 주입 | 귀속 가능 후보30, MAC_REJECTED30, 모호/미관찰0 |

오탐 분모는1초 단위 정상 구간이며 프레임 수가 아니다. 차단 관찰은 제한된 표본·payload 상관관계 기준이다.
C1/C2는 IDS OFF이므로 유형 NOT_EVALUATED가 정상이다. C1도 입력 검사를 수행한다.
360회는 offscreen 서비스 증거이며 실제 화면 수동 시험과 구분한다.

## 5. 문제와 해결 과정에서 남길 사항

- 첫 정상 캡처는 frames0이었다. COMPLETE 문구를 정상 데이터 확보로 오해하지 않고 제외·재수집했다.
- ECU IDS와 ECU 정상 송신은 다른 프로그램이다. 정상 송신을 유지한 채 별도 창에서 캡처해야 한다.
- 수동 worker의 빈 줄은 JSON 오류를 일으켰고 로그 폴더가 없어서 tee 저장도 실패했다. 후속 자동 입력 스크립트로 실행했다.
- 사용자 명령 앞에 불필요한 ssh를 붙여 실패한 시도는 공격 실험에 포함하지 않는다.
- 기존 자동 대시보드는 /opt/ivi 설치본, 실제 확인은 최신 build-handoff 일반 바이너리다. 자동실행 갱신·재부팅 검증은 미수행이다.
- MAC30회는 로컬 제어 스크립트로 수행했다. 이를 일반화한 CLI는 코드 검증됐으나 동일30회를 새 CLI로 다시 실행한 것은 아니다.

## 6. 로그와 문서 인수인계

[증거 릴리스](https://github.com/Solidvx/Capstone-proj/releases/tag/evidence-20261022)에서 로그 압축본과 체크섬을 받는다.
압축본의 README.txt, 두 총정리 문서, [인수인계 안내](../playbooks/three-node-handoff.md) 순서로 읽는다.

- PC: 예비시험 실패/성공,360회,MAC30회 로그 및 결과.
- ECU: 빈 캡처 실패, 정상 고정/조작 manifest·frames·평가 보고서, 당시 IDS 소스.
- IVI: 상세 처리 로그 수집 시점 스냅샷.
- Pi3: 수동/반복 공격 송신 증거와 당시 worker 소스.
- FILES.json: 원본/공유 해시와 비식별 처리 여부. SHA256SUMS: 공유 파일 검증.

원본 PC 설정과 키는 공유하지 않는다. 공유 사본은 비식별 처리로 원본 manifest와 해시가 달라질 수 있어 재개 입력으로 쓰지 않는다.
장비 소스는 직접 반영된 부분이 있어 git HEAD만으로 재현 버전을 판단하지 않는다. campaign 소스 해시와 스냅샷을 함께 확인한다.
수집 이후 로그가 추가됐을 수 있으며 현재 장비 프로세스 상태는 다음 담당자가 확인해야 한다.

## 7. 남은 일과 오늘 제외한 일

| 구분 | 작업 |
|---|---|
| 미완료 | flooding 부하에서 정상 BMS 갱신·손실·지연·BUS-OFF 등 가용성 평가 |
| 추가 검증 필요 | 반복 replay, C1/C2/C3 대조, fuzzy 필터 효과 및 일반화 가능한 차단율 |
| 오늘 명시적 제외 | 정식1,200회 실행, 재부팅 자동실행 확인 |
| 인수자 확인 | PR 머지 상태·장비 직접 수정본 보존·최신 실행 버전 통일 |

완료된 기본 동작 검증을 전체 보안 성능 검증 완료로 확대하지 않는다. 추가 실험은 새 run-id·폴더로 기록하고 기존 결과를 덮어쓰지 않는다.
