## 2. 장비 역할과 데이터 흐름

```text
PC ── SSH 관리 ──┬─ ECU: 정상 센서 데이터 송신, C3에서 IDS
                ├─ IVI: CAN 수신, SecOC, 데이터/경보 게시
                └─ Pi3: 키 없는 CAN 공격 모듈

가변저항 → ADS1115 → ECU ── CAN H/L ── IVI
                              ↑
                         Pi3 공격 주입
```

- ECU·IVI는 Raspberry Pi 4와 SEENGREAT CAN 확장 보드를 사용한다. ECU에는 E3P·ADS1115와 가변저항이 연결돼 있다.
- 공격 노드는 Raspberry Pi 3와 기존 MCP2515 장비를 사용한다. 버스는 500 kbit/s이다.
- PC가 실행·종료·로그 수집을 담당한다. SSH는 관리 경로이며 공격 프레임은 Pi3의 CAN 인터페이스에서 송신한다.
- SSH 개인키는 PC에, SecOC 키는 ECU·IVI에 둔다. Pi3에 SecOC 키를 전달하지 않는다.
- 실험 설정의 실제 주소·계정·키 경로와 원시 로그는 로컬 제외 경로에 보존하고 이 보고서에 복사하지 않는다.

| 구성 | SecOC | IDS | 의미 |
|---|---|---|---|
| C1 | OFF | OFF | 비교 기준. 입력 형식·범위 검사는 남아 있으므로 모든 입력을 무조건 수용하는 구성은 아님 |
| C2 | ON | OFF | SecOC 적용 |
| C3 | ON | rules+if | SecOC 및 IDS 적용 |

## 3. 초기 예비 시험에서 확인한 문제와 수정

### 3.1 실행 준비 및 계측 오류

초기 실행은 ECU의 비대화형 sudo 비밀번호 요구, CAN bitrate 불일치 때문에 공격 시작 전 중단됐다.
상태 조회에서 불필요한 sudo를 제거하고 CAN을 500 kbit/s로 설정했다.
fuzzy가 무작위로 보낸 0x200을 IDS 경보로 오인해 IDS OFF 조건을 중단시키는 판정 오류도 수정했다.
공격 송신 payload와 일치하는 후보를 구분하지만 payload 일치는 암호학적 송신자 증명이 아니다.

### 3.2 고속 혼합 공격의 복합 탐지

PC-PILOT-003은 12/12 유효였지만 C3 네 조건은 모두 COMPOUND였다.
모든 공격을 목표 1,000 frames/s로 주입한 조건이며 IDS FRAME_RATE 기준은 1초 구간 100프레임이다.

| 공격 | ECU와 IVI의 유형 목록 | 확인된 원인 |
|---|---|---|
| flooding | fuzzy, flooding | 미등록 ID 0x000과 높은 전송량 |
| fuzzy | fuzzy, spoofing, flooding | 미등록 ID 다양성, 일부 정상 ID의 범위 위반, 높은 전송량 |
| replay | replay, flooding | 과거 카운터와 높은 전송량/짧은 주기 |
| spoofing | spoofing, flooding | 값 급변·MAC 불일치와 높은 전송량/짧은 주기 |

C3 flooding 공격 전 정상 구간에서 IF_ANOMALY 1건도 관찰됐다. 이 단일 관찰만으로 정상 오탐률을 계산하지 않는다.

### 3.3 isolated-v1 분리 조건

| 공격 | 주입 조건 | 분리하려는 증거 |
|---|---|---|
| flooding | 목표 1,000 frames/s, 고정 ID 0x000 | 높은 전송량 |
| fuzzy | 5 frames/s, 기존 메시지·경보 ID를 제외한 무작위 표준 ID/payload | 미등록 ID 다양성 |
| replay | 5쌍/s, 관찰한 raw/auth를 연속 송신; C1은 raw만 | 과거 인증 카운터 |
| spoofing | 5 frames/s, SOC raw=201의 범위 초과 BMS | 위조 값의 범위 위반 |

단일 UNKNOWN_ID와 PERIOD_TOO_SHORT는 이상 기록으로 보존하되 특정 공격 유형을 단정하지 않는다.
최근 1초에 서로 다른 미등록 ID 3개 이상을 fuzzy로 분류하며 FRAME_RATE는 flooding 근거로 유지한다.
IDS에 실험의 공격 이름이나 정답을 입력하지 않는다. 실제 복합 징후는 COMPOUND로 보존한다.

**주입 조건과 IDS 규칙을 함께 변경했다. 이전 시험과의 비교를 순수한 탐지기 성능 향상으로 해석하지 않는다.**
이 분리 프로파일은 모든 fuzzy/spoofing 변종을 대표하지 않으며, 혼합 조건 mixed-v1은 별도 보존된다.

## 4. 360회 실험 과정과 결과

실행 식별자: `PC-TYPES360-001`. 선행 분리 예비 시험: `PC-TYPES-001`(12/12 유효).

- 3구성 × 4공격 × 30회 = 360회.
- 센서 모드 ads1115, 프로파일 isolated-v1.
- 회차별 기본 baseline 2초, 공격 3초, post 1초. Replay는 공격 구간에서 원본 수집 약 1초를 추가로 수행한다.
- PC가 조합별로 ECU·IVI·관찰기·공격 모듈을 실행하며 C3에는 IDS를 추가한다.
- 정상 실행에서는 한 조합의 30회 동안 프로세스를 유지하고 조합 전환 시 종료·재시작한다.
- IVI는 offscreen 실험 바이너리로 실행했다. 대시보드 창이 보이지 않아도 CAN 수신·SecOC·서비스 게시를 기록한다.

| 구성 | flooding | fuzzy | replay | spoofing | 합계 |
|---|---|---|---|---|---|
| C1 | 30 유효 / IDS 미평가 | 30 유효 / IDS 미평가 | 30 유효 / IDS 미평가 | 30 유효 / IDS 미평가 | 120 |
| C2 | 30 유효 / IDS 미평가 | 30 유효 / IDS 미평가 | 30 유효 / IDS 미평가 | 30 유효 / IDS 미평가 | 120 |
| C3 | 30 유효 / MATCH 30 | 30 유효 / MATCH 30 | 30 유효 / MATCH 30 | 30 유효 / MATCH 30 | 120 |

전체 완료360, 유효360, 무효0, 미완료0, attempt360, process session12, 최종 COMPLETE.
추가 재시도는 없었다. C3는 ECU IDS·IVI 게시 유형 모두 MATCH 120/120이며 각 공격별 30/30이다.
모든360회에서 ECU·IVI의 공격 payload 일치 후보를 관찰했다. Replay는 정상 프레임과 payload가 겹치므로 정확한 공격 도착률로 바꾸어 계산하지 않는다.

### 오류·중단·재개 정책

실행 옵션은 `--max-recoveries 2 --continue-on-error --no-can-reset`이었다.
유형 불일치·미탐·개별 INVALID는 기록하고 계속한다. 복구 가능 실행 오류는 제한 재시도한다.
재시도가 소진돼도 프로세스 종료 확인·로그 봉인·CAN 정상 확인이 되면 해당 조합의 남은 회차를 보류하고 다음 조합으로 넘어간다.
미완료가 남으면 PARTIAL로 보고하고 `--resume`으로 이어간다. 보류를 유효/완료로 세지 않는다.
로그 수집·저장 실패, 잘못된 설정, 종료 미확인, CAN 이상은 중단한다.
이번360회에서는 오류가 없어 물리 장비 복구 경로의 실증은 없으며 해당 경로는 단위 시험으로만 검증됐다.

## 5. 실제 IVI 대시보드 수동 확인

offscreen360회와 별도로 최신 `ivi_platform/build-handoff/ivi_dashboard`를 실제 Wayland 화면에 실행했다.
기존 자동실행은 `/opt/ivi/bin/ivi_dashboard`를 가리키며 그 설치본과 최신 빌드는 구분했다.
ECU의 ads1115 정상 송신을 켜고 가변저항 조작 시 화면 값 변화를 사용자가 확인했다.
ECU IDS를 실행한 뒤 Pi3 worker에 각 공격의 isolated-v1 명령을 순서대로 전달했다.

| 입력 | 사용자 관찰 |
|---|---|
| 가변저항 조작 | 화면 값 변화 반영 |
| flooding | Flooding Attack 표시 |
| fuzzy | Fuzzy Attack으로 전환 |
| replay | Replay Attack으로 전환; SecOC 색·문구 변화 |
| spoofing | Spoofing Attack으로 전환 |

증거 수준은 사용자 수동 관찰이다. 녹화·스크린샷 자동 검증은 없다.
SecOC 초록/노랑 변화 자체를 차단 성공으로 계산하지 않는다. 경보 해제 동작·화면 표시 지연·재부팅 자동실행은 미검증이다.
사용자가 대시보드를 종료한 뒤 재실행 명령을 안내했으나 현재 재실행 성공 여부는 별도 확인이 필요하다.

## 6. 정상 고정·조작 입력 오탐률 결과

사용자가 제공한 ECU 캡처 manifest 및 평가 출력에 따라 고정·조작 두 조건 모두 완료했다. 후속 인수인계 수집에서 장비의 fpr-report.json 및 캡처 원본도 확보했고 캡처 SHA-256을 대조했다. 고정 조건의 추가 이상2건은 IF_ANOMALY로 확인됐다.

### 실행 조건과 순서

1. Pi3 공격 모듈과 별도 실시간 IDS를 종료한다.
2. ECU 정상 송신(adaptive_ecu, ads1115, SecOC ON)을 유지한다.
3. 첫 측정은 가변저항을 고정한다. IVI 대시보드는 켜둘 수 있으나 정상 캡처의 필수 조건은 아니다.
4. `security.experiments.can_capture`로 physical can0를 300초 수집하고 `--normal`로 공격 없는 입력임을 확인한다.
5. `security.experiments.evaluate_normal`로 새 캡처를 평가한다. 이전 fit/calibration 캡처를 사용하며 새 평가 캡처를 학습·보정에 재사용하지 않는다.
6. SecOC 검증은 ECU의 기존 키를 사용한다. PC·Pi3로 키를 복사하지 않는다.

```text
ECU 정상 송신 ── CAN ── IVI 화면(선택)
                  └─ 300초 캡처 → 규칙-only / 규칙+IF 오프라인 평가
```

현재 방식은 실시간 IDS 경보를 화면에서 확인하는 시험이 아니다. 캡처 후 IDS로 평가한다.

### 계산과 유효성

- 기본 warmup 2초를 제외하고 길이=이동폭=1초인 완전한 구간을 사용한다.
- 구간 내 `result=ANOMALY`가 하나 이상이면 오탐 구간1개로 센다. 여러 이벤트를 분모보다 많이 더하지 않는다.
- 오탐률 = 오탐 구간 수 / 유효 평가의 전체 완전 구간 수.
- 약300초 수집이지만 정확한 분모는 보고서의 complete_windows를 사용한다. 두 실행에서 실제 평가 출력은 각각298구간이었다.
- 수집 완료·공격 없음 확인·손실/오류 없음·파일 해시·시간 순서를 확인한다.
- 평가기는 빈 구간이 있거나 완전 구간이100개 미만이면 INVALID로 판정한다.
- 공식 TC-EXP-005 목표는 ≤5%다. 현재 평가기는 유효 조건에서 이를 PASS/FAIL에 사용한다.
- rules-only와 rules+if를 분리해 보고한다. IF 단독 오탐·IVI 실제 경보 오탐률은 현재 요약과 같지 않으며 별도 집계가 필요하다.
- 유형0의 이상 이벤트도 ANOMALY이면 분자에 포함된다. 따라서 유형 경보가 없다는 사실만으로 오탐0을 선언하지 않는다.

| 항목 | 고정 입력 | 조작 입력 |
|---|---:|---:|
| 캡처 시간(초) | 300.0044229770001 | 300.0077544479991 |
| 프레임 수 | 5,996 | 6,000 |
| CAN 오류 / 수신 드롭 | 0 / 0 | 0 / 0 |
| 완전 평가 구간 수 | 298 | 298 |
| rules-only | PASS, 0/298 = 0% | PASS, 0/298 = 0% |
| rules+if | PASS, 2/298 ≈ 0.67% | PASS, 0/298 = 0% |

고정 캡처 SHA-256: `174fe9f612b5c6a71424b21ddb986495980510e1136d2ab607bbe753f65a5186`.
조작 캡처 SHA-256: `80b7b74a4851b8b60e7e129fffd31b6ce7825a7cc66a2d122bf6aa474a2aa806`.
저장 위치는 ECU 저장소의 `tmp/normal-check-<시각>/`, `tmp/normal-move-<시각>/`이며 정확한 디렉터리 시각은 미수집이다.
각 폴더의 manifest.json, frames.jsonl, fpr-report.json을 보존한다.

조작은 사용자 보고상 화면 값 약16~80 사이 이동, 약70에서 고정, 다시 이동이다.
표시 항목과 단위는 확인되지 않았으므로 SOC/전압으로 단정하지 않는다.
제안한 절차는 고정1분→조작1분→고정1분→반대방향 조작1분→고정1분이지만 실제 구간별 시각·속도는 검증하지 않았다.
고정 조건의 규칙+IF 오탐2구간은 이벤트2건과 다르며, 원본 reasons는 IF_ANOMALY:2이며 규칙 위반 reason은 없다.
두 조건은 별도로 보고하며 모든 정상 상황의 오탐률0을 주장하지 않는다.

최초 수집에서는 300.00682559399957초 동안 frames=0이었다. 수집 프로세스 COMPLETE여도 평가 불가한 빈 캡처이며 정상 오탐률 분모에서 제외한다.
이후 ECU 정상 송신과 별도 IDS 프로세스를 구분하고 정상 송신을 유지한 상태에서 재수집했다.

출력 `fpr-report.json`과 manifest를 보존한다. 실패하면 원본을 남기고 원인을 분석하며 평가 데이터로 임계값을 조정한 뒤 동일 데이터를 독립 평가처럼 재사용하지 않는다.

## 7. 기존 로그에서 확인한 거부 증거

`inspect_ivi_rejections`는 봉인된 원본 로그 해시를 확인하고 IVI와 관찰기의 같은 호스트 시간 구간을 사용한다.
송신 payload와 일치하는 처리 후보만 집계하며, 공격 발신자 귀속을 확정하지 못하는 상황에서는 blocking_rate를 null로 남긴다.

| 조건 | IVI 일치 후보 처리 | 해석 |
|---|---|---|
| C2 replay | auth 후보480: published30 / rejected450 | 공격 단계 안의 원본 수집 auth도 일치하므로 published30을 공격 성공으로 계산하면 안 됨 |
| C3 replay | auth 후보480: published30 / rejected450 | 같은 한계; 카운터 거부 증거 존재 |
| C1 spoofing | rejected451 | 입력 범위 검사; SecOC OFF에서도 거부 |
| C2 spoofing | rejected451 | 입력 범위 검사; SecOC 효과 아님 |
| C3 spoofing | rejected450 | 입력 범위 검사; SecOC 효과 아님 |
| flooding / fuzzy | 해당 IVI FRAME 후보0 | 수신 필터 영향; 도착하지 않았거나 전부 차단됐다는 뜻 아님 |

숫자는 후보 처리 이벤트 수이며 공격별 차단율의 분자·분모로 확정한 값이 아니다.


## 8. 추가 인증 거부 시험 결과

### 8.1 공통 조건과 증거 수준

ECU ads1115 정상 송신·SecOC ON, IVI 최신 대시보드 SecOC ON 및 observation-jsonl 기록을 유지하고 별도 IDS는 종료했다.
Pi3는 키 없이 CAN으로 주입했다. 이번 시험은 유형 경보가 아니라 IVI 처리 결과와 연결 원본을 확인한다.
근거는 사용자가 출력한 Pi3 송신 로그 집계와 IVI payload 필터 결과이다. 후속 인수인계에서 해당 Pi3·IVI 로그 스냅샷을 PC로 수집했다. 장비 원본의 별도 서명은 없으며 수집 파일 해시로 이후 무결성을 관리한다.
IVI 증거는 사용자 홈의 `ivi-evidence/block-check-20261022-060541/ivi.jsonl`에 저장됐다.

### 8.2 Replay 소규모 시험

첫 실행은 저장 폴더 부재와 빈 JSON 입력으로 실패했으며 완료 공격/성공 분모에서 제외했다.
후속 BLOCK-REPLAY-002는 자동 stdin 전달로 실행해 종료 코드0, ATTACK_DONE을 확인했다.

| 항목 | 결과 |
|---|---|
| 송신 | raw0x100 16개 + auth0x102 16개 = 총32프레임 |
| TX 오류 / worker 수신 드롭 | 0 / 0 |
| own echo | 31; 송신32와 다르므로 echo를 원격 도착 증명으로 사용하지 않음 |

일반적인 replay 차단율100% 또는 카운터 검사16/16 성공으로 확대하지 않는다.

### 8.3 파싱 가능한 변조 인증 시험

기존 SOC raw201의 범위 초과 spoofing 대신, 관찰한 정상 raw를 SOC raw100으로 변경했다.
관찰 auth의 MAC 바이트를 변조하고 counter를 관찰값+50으로 변경해 키 없이 한 쌍을 주입했다.
카운터 허용 여부는 의도만으로 확정하지 않고 실제 IVI 거부 사유로 확인했다.

| 항목 | 결과 |

| 위조 auth0x102 | `2a5233a000003efb`, counter16123 |

### 8.4 반복 MAC 거부30회

PC 제어 실행: `mac-repeat-20261022-061633`. 정상 인증 게시가 최근에 존재하는지 확인한 뒤,

PC가 IVI의 auth payload 및 source_data를 대조해 중복/미관찰/다른 원본을 분리했다.

| 항목 | 결과 |

## 9. 남은 검증과 후속 계획

### A. 정상 오탐률 상세 결과 보존

고정·조작 기본 측정은 완료했다. 두 fpr-report.json과 manifest를 PC에 보존하고 고정 조건의 이상2구간 reason을 확인한다.
추가 환경에서 재보정하는 경우에는 학습·보정·최종 평가를 다시 분리한다.

### B. 인증 차단 시험

Replay 및 파싱 가능한 변조 인증의 소규모 거부 확인은 위8절에 기록했다.
정량적인 일반 차단율이 필요하면 시험 수·분모·주입 경계를 사전 고정하고 C1/C2/C3 대조 및 반복을 수행해야 한다. 공격자는 계속 키 없이 동작한다.

| 시험 | 필요한 증거 | 지표 |
|---|---|---|
| replay | 원본 수집 단계와 주입 단계 분리, 과거 raw/auth, IVI 도착·카운터 거부 | 평가 가능한 재전송 인증 시도 중 거부 비율 |
| spoofing | 파싱 가능한 변조 raw/auth 연결, IVI MAC 실패·미게시 | 평가 가능한 변조 인증 시도 중 거부 비율 |
| 인증 프레임 없는 raw | pending·timeout·정상 프레임에 의한 교체 구분 | 별도 미인증 처리 결과; MAC 실패와 합산하지 않음 |
| fuzzy | 버스 관찰과 수신 필터·파서 거부 구분 | 비정상 입력 수용/거부; SecOC 차단과 분리 |
| flooding | 정상 BMS 갱신·유실·지연·BUS-OFF | 가용성 유지 효과; 인증 거부율로 대체하지 않음 |

차단율은 IVI에서 관찰된 **공격 귀속이 검증된 평가 가능 시도**를 분모로 고정한다.
송신 횟수만을 분모로 삼아 유실을 차단으로 세지 않는다. 원본 수집·정상 payload 충돌·누락·모호한 대응은 별도 건수로 보고한다.
전체 모호 사례를 감춘 채 일부만의 비율을 전체 성공률로 표현하지 않는다.
현재 도구만으로 일반 차단율을 계산했다고 선언하지 않으며, 계측 구현 후 작은 예비 시험부터 수행한다.

### C. 최종 보고와 확대 실행 — 오늘 제외한 범위

사용자는 공식1,200회와 재부팅 자동실행 확인을 오늘 수행하지 않기로 명시했다. 추후 별도 일정으로 남긴다.
현재360회는 그대로 보존하며 변경된 공격 조건·IDS·모델 버전의 결과를 같은 실험으로 합치지 않는다.
