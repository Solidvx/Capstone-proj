# SPI-CHECK-001 / DIAG-SPI1M-001: 첫 비교 시험에서 오류 미재현

ECU 원본 9개 파일을 `../raw/SPI-CHECK-001/ecu/`에 보존했다. [분석 결과](../analysis/spi-check-001-ecu.json), [원본 해시 목록](../inventory.json)을 참조한다.

- 실행 기록: 2026-10-04 04:42:48~04:44:48 KST, timeout 종료코드 124, 앱 종료 메시지 확인.
- ECU CAN 캡처: 2398프레임. 0x100 BMS와 0x102 인증 각각 1199건, 교대 순서 및 DLC 8 확인.
- 인증 counter: 0~1198 연속, 불연속 없음. 이것은 counter 검사이며 MAC 검증을 수행한 것은 아니다.
- ECU TX: 16678→19076, 증가량 2398로 캡처 건수와 일치. TX 오류 및 bus-off 등 표시 오류 카운터는 전후 모두 0.
- 캡처에서 CAN error flag 프레임은 0건. ECU의 관측 결과만으로 IVI 수신 정상성을 보장하지 않는다.

이번 시험은 IVI SPI 최대 주파수를 100kHz에서 1MHz로 변경한 뒤 비교하기 위한 진단이다. 변경 후 IVI 적용값 증거, 재부팅 이후 실행 환경, 수신 JSONL, CAN 원본과 전후 통계는 수령 대기다. ECU 로그만으로 변경 적용이나 오류 해결을 선언하지 않는다. IVI 자료 대조 후 첫 회 판정을 하고 후속 반복 여부를 결정한다.

## 04H49M IVI 자료 수령 후 최종 대조

위 수령 대기는 해소됐다. ECU 시험 ID는 SPI-CHECK-001, IVI는 DIAG-SPI1M-001이다. 사용자의 동일 실행 전달 맥락, 수집 시간 구간 및 전체 프레임 순서·payload 일치로 대응시켰다. 원본 ID를 바꾸지 않았다. IVI 원본은 `../raw/SPI-CHECK-001/ivi/`이며 [교차 분석 JSON](../analysis/spi-check-001-crosscheck.json)에 결과를 보존했다.

| 점검 | 결과 |
|---|---|
| ECU 대 IVI CAN | 각각 2398프레임, 모든 ID·payload·순서 일치, 차이 0 |
| IVI CAN 대 앱 FRAME 기록 | 2398행 전체 일치 |
| 정상 인증 | 1199건, secoc_on 모두 true |
| 인증 거부 및 기타 receiver 기록 | 0건 |
| 인증 counter | 0~1198 연속 |
| IVI RX 증가량 | 0→2398, 캡처 건수와 일치 |
| IVI 오류 카운터 | RX errors/dropped, bus-off 및 표시 CAN 오류 통계 전후 모두 0 |
| BMS 주기 | 1198간격, 99.927~100.236ms, 90~110ms 이탈 0 |
| 설정 변경 | config 전후 diff는 spimaxfrequency 100000→1000000 한 항목 |
| 변경 후 적용 | Device Tree 1000000, CAN 500kbps 유지, IVI 커널 6.18.29 유지 |

**판정: 설정 변경 및 재부팅 후 첫 120초 비교 시험에서 오류 미재현.** 수집한 구간에서 양측 누락·변조 차이는 발견하지 못했다. SPI 변경뿐 아니라 재부팅으로 장치 상태도 초기화됐으므로 이번 결과만으로 SPI 속도가 유일한 원인이라고 확정하지 않는다. 기존 공식 성능 시험의 보류 판정을 소급해 PASS로 바꾸지 않는다. 이번에는 지연 CSV를 평가하지 않았다.

다음은 같은 설정을 유지한 120초 진단 2회를 추가해 총 3회 확인하는 것이다. 다음부터 양측 시험 ID를 DIAG-SPI1M-002, DIAG-SPI1M-003으로 통일한다. 매회 새 파일을 사용하고 CAN 전후 통계·전체 수집 구간·정상 인증 거부 여부를 함께 보존한다. 새 ECU 실행에 앞서 IVI 담당자가 수신기의 재실행 및 인증 counter 초기 상태를 준비했는지 확인한다.
