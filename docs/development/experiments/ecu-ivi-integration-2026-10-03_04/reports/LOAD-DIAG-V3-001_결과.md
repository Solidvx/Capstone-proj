# LOAD-DIAG-V3-001 ECU 진단

## IVI 수령 후 교차검증

07H43M archive를 보존했다. [양측 분석](../analysis/load-diag-v3-001-crosscheck.json). ECU 관측 5,566프레임은 IVI 앞부분과 모두 일치하며 IVI에는 마지막 정상 BMS·인증 한 쌍이 추가되어 5,568개다. ECU TX 증가·IVI RX 증가·IVI CAN 수량 모두 5,568이다. 주입 ID 0x000 5,425개 모두 IVI에서 관측됐다. 필터 대상 143개는 receiver FRAME과 순서·payload 모두 일치한다.

최대 점유율 표시는 46%(07:41:25 및 26 KST)로 50% 조건 미달. IVI 인증 게시63, AUTH_TIMEOUT13(타이머 레코드 포함), AUTH_ORPHAN2. CAN 오류·드롭·bus-off 증가는 없으며 세 프로세스 종료코드0, candump/canbusload stderr는 비어 있다.

따라서 실제 송신 성공한 프레임의 양측 불일치 증거는 없고, 송신 이전 경로의 ENOBUFS 1,828건과 정상 인증 전달 저하가 확인됐다. 정상 전달 저하와 저부하를 구분한다. 46% 미달 원인을 특정 SPI 주파수나 qlen 하나로 확정할 수 없다. 같은 조건 반복이나 송신률 증가보다 ECU 송신 경로·장비 설정 근거 검토가 다음 작업이다. Config 3 기능 pilot과 공식 부하 인수는 분리 가능하지만 이번 결과를 공식 부하 합격으로 변경하지 않는다.

## 최초 ECU 수령 기록

사용자가 전달한 archive를 raw/LOAD-DIAG-V3-001/ecu에 보존했다. [분석](../analysis/load-diag-v3-001-ecu.json). manifest 결과 해시를 모두 검증했다. IVI 자료는 아직 미수령이다.

| 항목 | 실측 |
|---|---|
| 시행 | INVALID, 사유 TX_ERRORS, manifest ERROR, 사용자 출력 exit 2 |
| 공격 송신 성공 / echo | 5,425 / 5,425 |
| 송신 오류 | 1,828건 모두 errno 105 |
| ECU 관측 드롭 | 0 |
| 공격 구간 정상 원본 / 참조 게시 | 15 / 2 (기대 30) |
| ECU TX 증가 | 68,075→73,643, 5,568프레임 |
| CAN 오류·드롭·bus-off 통계 증가 | 0 |
| 실행 시각 | 2026-10-04 07:41:18~07:41:29 KST |

Linux errno 105는 ENOBUFS다. 송신 요청 시 버퍼 자원을 확보하지 못한 오류로, 이전 OSError만 있던 기록보다 원인 범위가 좁혀졌다. qlen은 10으로 기록돼 있으나 이 값만으로 특정 큐가 유일한 원인이라고 단정하지 않는다. SPI 처리량·드라이버·송신 경로 중 최종 병목은 미확정이다. CAN 인터페이스 errors=0과 애플리케이션 송신 실패는 서로 다른 계층의 지표다.

v3의 오류 무효 판정과 errno 기록은 실장비에서도 동작했다. 실제 부하와 양측 프레임 일치는 IVI 자료 수령 후 판정한다. 큐 확대나 송신률 증가를 즉시 적용하지 않으며 기존 정상 IF 오탐 평가 통과는 유지한다.
