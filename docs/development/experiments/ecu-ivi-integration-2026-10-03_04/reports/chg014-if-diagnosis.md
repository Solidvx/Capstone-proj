# IF 정상 오탐 후속 진단 — 2026-10-03

## 현재 결론

**기존 저장 결과에서 오탐 16건의 이유가 모두 `IF_ANOMALY`임을 확인했다. 규칙·MAC 오류가 섞여 14.81%가 된 것은 아니다. 다만 IF가 왜 해당 창을 이상으로 판단했는지는 아직 확정하지 않았다.** 제품 코드·모델 설정·임계값과 기존 평가 자료를 변경하지 않았다.

이 문서는 CHG-014 후속 임시 분석이다. 인증 오류 후 사용자 요청으로 재시도해 모델 진단 실행을 완료했다. 아래 결과는 기존 합성 자료의 재현·진단이며 새 물리 성능 측정은 아니다.

## 재시도 실행 결과

WSL의 기존 Python 환경에서 정상 종료(exit 0). scikit-learn 1.9.1. [진단 JSON](../analysis/chg014-if-diagnosis.json)에 결과를 보존했다.

| 항목 | 결과 | 해석 |
|---|---|---|
| 기존 독립 평가 재현 | **16/108창, 14.81%, FAIL** | 이전 저장 결과와 오탐 수·분모·이유별 건수 일치 |
| 학습 자료를 런타임 경로로 재생 | **7/108창, 약 6.48%, FAIL** | 같은 자료에서도 학습과 런타임의 창이 달라짐. 독립 평가 수치로 사용하지 않음 |
| 원래 학습 특징 벡터 | 105개 중 음수 decision 6개 | 학습 데이터도 전부 정상 판정되는 설정은 아님. 런타임 창 오탐률과 분모가 다름 |
| 평가의 런타임 특징 범위 | 프레임 수 학습 19~22, 런타임 18~22 | 창 구성 차이가 실제 특징값에 나타남 |
| 학습 범위 이탈과 이상 판정의 동시 발생 | 각 특징에서 0회 | 단순히 특징이 학습 최소·최대를 벗어났기 때문에 오탐했다고 설명할 수 없음 |

마지막 두 행의 특징 통계는 워밍업 포함 IF 호출 기준이다. 평가 호출은 108회, 그중 이상 호출은 17회이며, 워밍업을 제외한 최종 오탐 창은 16개다. 호출 수와 최종 평가 창 수가 우연히 같아도 같은 집합은 아니다.

**진단 결론:** 학습·런타임 창 차이는 확인됐지만 오탐의 단일 원인으로 확정되지 않았다. 오탐 호출은 각 특징의 학습 최소·최대 범위 안에서도 발생했다. 다음 분석은 특징들의 조합·점수 분포와 창 생성 방식의 통제 비교가 필요하다. 임계 완화나 특징 제거 없이 원래 FAIL을 유지한다.

## 재실행 준비와 현재 제약

[진단 스크립트](../tools/chg014-if-diagnose.py)를 작성했다. 기존 자료를 읽어 학습 특징·런타임 특징의 범위, 학습 자료 재생 시 오탐, 평가 자료 오탐을 비교하고 JSON으로 저장하도록 구성했다. 기존 평가의 16/108과 이유별 건수가 일치하는지도 검사한다. 학습 자료 재생 결과는 독립 성능 평가로 사용하지 않는다. 특징 통계의 호출 수는 워밍업을 포함하므로 최종 FPR 분모와 구분한다.

처음에는 WSL 접근 및 자동 승인 검토의 로그인 토큰 오류로 실행하지 못했다. 이후 사용자의 재시도 요청에서 정상 실행됐고, 기존 결과와의 일치 assertion도 통과했다. 승인 검사를 우회하지 않았다.

실제로 사용한 명령은 다음과 같다. 프로젝트 루트의 WSL에서 실행했다.

```sh
PYTHONPATH=. /home/radix0/venvs/capstone-security/bin/python tmp/chg014-if-diagnose.py
```

출력 파일 `tmp/chg014-if-diagnosis.json`이 생성됐다. 동일 명령을 다시 실행하면 기존 파일 덮어쓰기를 거부하므로, 추가 진단은 별도 출력 경로를 사용해야 한다.

## 다음 검증과 수정 결정

**작업 상태: 사용자 요청에 따라 후속 할 일로 등록하고 현재 보류(2026-10-03).** 추가 원인 분석·코드 수정·임계 조정·재평가는 지금 진행하지 않는다. 아래 항목은 추후 재개할 작업이며, 기존 14.81% FAIL과 진단 결과를 그대로 보존한다. 전체 진행상황 문서의 다음 행동 표와 14절에도 별도 과제로 등록했다.

1. **완료:** 진단 스크립트로 기존 FAIL을 재현하고 창 경계·특징 범위 차이를 확인했다. 다음에는 별도 진단 자료에서 창 생성 방식과 특징 조합의 영향을 통제 비교한다.
2. 창 생성의 일관성 문제가 재현되면 학습·실시간 경계를 명세에 맞춰 정리하고 회귀 시험을 추가한다. 아직 제품 수정은 하지 않았다.
3. 사용자가 실제 정상 CAN 자료를 별도 학습·조정·최종 평가 구간으로 수집한다. 정상 상태 변화와 Fail-safe 이벤트 등 필요한 운용 조건을 기록한다.
4. 조정이 필요하면 조정 자료에서 결정하고, 남겨둔 독립 자료로 최종 FPR와 탐지 성능을 함께 평가한다. 기존 FAIL 자료는 진단에 사용했으므로 이후 수정의 최종 독립 평가 근거로 재사용하지 않는다.
5. TC-EXP-005는 물리 자료로 판정한다. 합성 재평가가 개선되더라도 물리 PASS로 바꾸지 않는다.

현재 전체 계획의 위치는 그대로다. **IF 평가 도구는 구현됐고, IF 성능 문제의 원인 규명·개선 및 물리 정상 오탐 인수는 남아 있다.**
