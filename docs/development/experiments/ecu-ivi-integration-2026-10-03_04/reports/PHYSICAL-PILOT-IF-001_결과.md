# PHYSICAL-PILOT-IF-001 ECU 분석

## IVI 수령 후 대조

07H52M 원본을 보존했다. [대조 JSON](../analysis/physical-pilot-if-001-crosscheck.json). ECU 관측8,926개는 IVI8,938개의 앞부분과 ID·payload·순서 모두 일치한다. IVI 추가 끝부분12개를 포함한 RX 증가도8,938이다. IVI receiver FRAME3,521개는 CAN 필터 대상과 모두 일치한다. IDS event published92건, 정상 인증 게시271건 확인. 경보 로그는 화면 픽셀 표시 증거와 구분한다. 전달 파일에 화면 캡처는 없다.

중단 경보에 해당하는 정상 인증 counter 0xfe→0xff의 **IVI candump 간격은100.017ms**다. ECU 참조99.930445ms와 일관되고 IDS 사용자 공간 기록45.850631ms와 다르다. 따라서 해당 사건의 50ms 미만 판정은 양측 CAN 관측으로 뒷받침되지 않는다. IDS의 recv 후 time.monotonic 기반 시각 측정이 처리 지연의 영향을 받은 근거가 확보됐다. IF 연산 자체와 스케줄링 중 어느 것이 지연을 일으켰는지는 미확정이다.

IVI 오류·드롭·bus-off 증가0, 세 프로세스 종료코드0, 수집 stderr 비어 있음. 최대 점유율 표시24%. 이번은 부분 기능 pilot이며 공식 flooding50% 시험으로 인정하지 않는다. 다음 수정 대상은 IDS 수신 시각 계측이며, 임계 완화·baseline 경보 무시는 하지 않는다. IVI나 ECU 추가 실행 없이 로컬 수정·검증 후 전달한다.

원본을 raw/PHYSICAL-PILOT-IF-001/ecu에 보존하고 manifest 결과 해시를 검증했다. IVI 대조는 대기다. 전체 run은 ERROR·exit 2이며 spoofing은 주입 전 baseline 검사에서 INVALID 처리됐다.

| 공격 | 시행 | 주입 송신/관측 | 최초 경보 관측 지연 |
|---|---|---|---|
| flooding | VALID | 2771/2771 | 0.791ms |
| fuzzy | VALID | 2657/2657 | 0.788ms |
| replay | VALID | 2876/2876 | 1.172ms |
| spoofing | baseline 중단, 미주입 | 미실행 | 미측정 |

앞 3종은 송신 오류·관측 드롭 0, 규칙 이벤트가 있고 공격 평가 구간 IF 이벤트는 각각 0이다. 따라서 규칙+IF 모드 구동은 확인했지만 IF가 공격을 탐지했다고 주장하지 않는다. 전체 IDS 로그 IF_ANOMALY는 1개로, 이번 중단 경보와 구분한다. replay 공격 게시 1건은 기존 넓은 출처 정의에 따른 원본 결과로 보존한다.

## 중단 경보의 실제 근거

spoofing baseline 원본 범위는 monotonic 42567.5841184~42569.583881345. IDS는 42568.682889717에 CAN ID 258(0x102), PERIOD_TOO_SHORT, attack_type4를 발생시켰다. 참조 관측기는 42568.683878754에 대응 경보 0x200 payload 046401026ac18672를 수신했다. baseline 경보 차단은 정상 동작했다.

같은 정상 인증 프레임 두 개의 관측 시각:

| 관측기 | 이전 인증 프레임 | 다음 인증 프레임 | 간격 |
|---|---|---|---|
| ECU 참조 수신기 | 42568.583003919 | 42568.682934364 | 99.930445ms |
| IDS 프로세스 | 42568.637039086 | 42568.682889717 | 45.850631ms |

IDS의 이전 프레임 읽기 시각만 참조보다 약54ms 늦다. runtime.SocketCan.receive는 커널 수신 시각이 아니라 recv 이후 time.monotonic을 사용하며 같은 루프에서 IF 연산과 로그 처리를 한다. 따라서 실제 버스 단주기보다 IDS 처리 지연/큐 적체에 따른 사용자 공간 시각 왜곡이 의심된다. IF 연산이 직접 원인인지 프로세스 스케줄링인지 이 로그만으로 확정하지 않는다. 단순히 임계 50ms를 낮추거나 baseline 경보를 무시하는 수정은 하지 않는다.

다음은 IVI candump의 동일 프레임 간격을 대조하고 IDS 수신 시각·계측 방식을 검토하는 것이다. 이번 사건을 IF_ANOMALY 중단 또는 물리 정상 IF 1/298 결과의 실패로 바꾸지 않는다. 실시간 규칙 판정의 신뢰성과 IF 공격 탐지 인수는 별도로 남아 있다.
