사용자가 전달한 실제 RPi 시험 자료의 분석이다. ECU는 develop 9568d90, constant 입력·SecOC ON·can0 500kbps. ECU 빌드 및 CTest 16/16 통과는 사용자 실행 출력으로 확인했다. 사용자는 대시보드 표시 성공과 Ctrl+C 수동 종료를 보고했다. 30초 완주로 기록하지 않는다.

## 현재 판정

- IT-001 / TC-INT-001: 실제 전달·인증·화면 동작 증거 확보. 화면은 사용자 관찰이며 공식 동작 영상과 IVI 실행 버전은 미확보.
- IT-003 정상 인증 경로: 제공된 225쌍에서 성공. TC-INT-002 전체는 키 불일치/변조 거부·미반영 시험까지 필요하므로 미완료.
- TC-PERF-002: 앱 로그 간격은 목표 범위 내. 원본 절대시각 CAN 캡처, 시각 의미와 수집 손실 조건 확인 후 최종 판정.
- TC-PERF-001: T1→T4 렌더 시각과 1,000개 이상 표본이 없어 미판정.
- EXQ-8: SecOC ON 제품 로그가 전달됐지만 OFF 모드 구현 완료의 증거는 아님.

## 다음에 받을 자료

1. 전달본 manifest 원본 및 미커밋 변경을 포함한 보존 소스의 위치. 기반 커밋만으로 실제 실행 소스와 동일하다고 취급하지 않는다.
2. 담당자가 제시한 IVI 명령이 실제 실행 명령인지 확인. 설명이 “앞서 안내한 대로 실행했다면”이라는 조건부 표현이므로 실제 셸 기록 확인과 구분한다.
3. candump 실행 명령/옵션 확인. 제공 로그는 프레임 간 delta 형식으로 보이므로 공식 성능 시험의 절대시각 캡처와 구분한다.
4. IVI 로그 수집 시작·종료가 ECU 송신 전체를 포함하는지 확인. TX 증가 704와 수신 로그 450 차이를 임의의 손실로 판정하지 않음.

근거 기준: [TEST_PLAN](../../../../TEST_PLAN.md)의 TC-INT-001·002, TC-PERF-001·002. IF 개선은 사용자 요청대로 보류 유지.

## 2026-10-04 일괄 답변과 00H53M manifest 인수

[HANDOFF-MANIFEST.json](../raw/received/00H53M/HANDOFF-MANIFEST.json)을 직접 파싱했다. schema는 `pi-source-handoff-v1`, kind는 `WORKTREE-SNAPSHOT-NOT-COMMIT`, base_commit은 앞선 보고와 일치하며 144개 파일 해시가 있다. 키·빌드·원시 로그 등은 제외 대상으로 명시돼 있다. 이 manifest에는 latency 이름의 파일 항목이 없으며, 담당자의 집계 스크립트 미포함 설명과 부합한다. archive 및 실제 Pi 바이너리는 받지 않았으므로 배포 archive 해시와 실행 바이너리의 일치 검증까지 수행한 것은 아니다.

담당자가 앞서 제시한 대시보드 명령으로 실제 실행했다고 확인했다. candump 명령은 `candump -td can0 | tee team-normal-001/can.log`로 확인됐으므로, 위 delta 시간 해석은 이제 명령으로 뒷받침된다. Git 오류 재확인·지난 실행 명령 재질문은 종료한다.
