## 1. P1의 목적

P1은 로컬 보관본 `/Desktop/도토리팀_소스코드/Cap-proj/ivi_platform`을 현재 저장소에 통째로 합치는 작업이 아니다. 재사용 가능한 C++/QML 파일을 선별하고, 현재 `docs/ICD.md`와 `adaptive_ecu/`의 실제 송신 형식에 맞춰 Node B IVI의 재현 가능한 빌드 기반을 만드는 단계다.

이번 P1에서는 다음을 완료 조건으로 삼았다.

- Qt가 없는 환경에서도 parser, SecOC, service와 시험을 빌드할 수 있다.
- Debug와 Release에서 동일한 명시적 검사를 실행한다.
- 보호 대상 BMS·Fail-safe 데이터는 SecOC 인증 성공 뒤에만 게시한다.
- ECU 공개 더미 벡터로 양측 HMAC 입력과 payload 해석이 일치한다.
- Android/AOSP 자리표시자, 빌드 산출물과 실제 키를 반입하지 않는다.

## 2. 사용한 입력과 선별 기준

| 입력 | 확인·적용 내용 |
|---|---|
| 로컬 보관본 `ivi_platform/` | parser, SecOC verifier, Qt/SocketCAN 구조의 참고 구현 |
| `adaptive_ecu/src/bsw/can_publisher.cpp` | BMS·Fail-safe 8바이트 payload 인코딩 |
| `adaptive_ecu/src/bsw/secoc_module.cpp` | HMAC-SHA256 입력 순서와 rolling counter 허용 범위 |
| `adaptive_ecu/test/test_secoc.cpp` | 더미 키 `00..1f`, 알려진 MAC, counter 경계 벡터 |
| `docs/ICD.md` | CAN ID, DLC, byte order, scale, SecOC 계약의 최종 기준 |

보관본의 parser/verifier 및 시험 6개 파일은 `plan/IVI_PLAN_B_전환계획.md`에 기록된 SHA-256과 일치함을 확인했다. 과거 구현에서 발견한 인증 전 원본 게시, signed counter 비교, BMS 갱신 시 IDS 경고 해제 동작은 그대로 가져오지 않았다.

## 3. 구현 내용과 결과물

### 3.1 빌드 구조

- [`ivi_platform/CMakeLists.txt`](../../../../../ivi_platform/CMakeLists.txt)
  - C++17, OpenSSL, Threads를 공식 core 의존성으로 구성했다.
  - `ivi_core`, `ivi_socketcan`, `ivi_dashboard` target을 분리했다.
  - Qt 6가 없으면 대시보드 target만 건너뛰고 core와 시험은 계속 빌드한다.
  - Qt 6.2 이상을 대상으로 Ubuntu 22.04 계열과의 호환 기준을 잡았다.

### 3.2 CAN·SecOC 계층

- [`ivi_platform/hal/can_types.h`](../../../../../ivi_platform/hal/can_types.h): CAN ID 5개, 8바이트 payload, MAC·키와 파싱 결과 자료형
- [`ivi_platform/hal/can_parser.cpp`](../../../../../ivi_platform/hal/can_parser.cpp): BMS, Fail-safe, 인증, IDS payload 파싱과 예약 필드 검사
- [`ivi_platform/hal/secoc_verifier.cpp`](../../../../../ivi_platform/hal/secoc_verifier.cpp): HMAC-SHA256 앞 4바이트 constant-time 비교와 unsigned counter delta `1..100`
- [`ivi_platform/hal/socketcan_receiver.cpp`](../../../../../ivi_platform/hal/socketcan_receiver.cpp): Linux SocketCAN의 허용 ID 필터, SFF/DLC 8 검사, RTR·ERR·EFF 제외, 종료용 wake pipe

ECU 예제 BMS payload `96 BE 10 68 FF EC 41 00`은 SOC 75%, SOH 95%, 42.0V, -2.0A, 25°C로 해석된다. 더미 키와 counter 0에서 계산한 MAC `D0 DD FC 05`도 ECU 시험 벡터와 일치한다.

### 3.3 상태 서비스

- [`ivi_platform/service/vehicle_data_service.cpp`](../../../../../ivi_platform/service/vehicle_data_service.cpp)
  - BMS와 Fail-safe 원본을 서로 다른 pending 슬롯에 보관한다.
  - 대응 인증 성공 전에는 `VehicleSnapshot`의 보호 데이터를 갱신하지 않는다.
  - MAC·counter 실패 시 마지막 정상값과 마지막 정상 counter를 유지한다.
  - BMS와 Fail-safe의 counter 상태를 분리한다.
  - IDS `0x200` 상태를 BMS 갱신으로 자동 해제하지 않는다.
  - 32바이트 SecOC 키 파일만 허용하며 키 파일 자체는 저장소에 넣지 않는다.

### 3.4 Qt/QML 기준 화면

- [`ivi_platform/ui_qml/main.cpp`](../../../../../ivi_platform/ui_qml/main.cpp): 키·CAN 인터페이스 인자, service/receiver/view model/QML 조립
- [`ivi_platform/ui_qml/dashboard_view_model.cpp`](../../../../../ivi_platform/ui_qml/dashboard_view_model.cpp): worker에서 받은 snapshot을 Qt GUI thread로 전달
- [`ivi_platform/ui_qml/qml/Main.qml`](../../../../../ivi_platform/ui_qml/qml/Main.qml): WAITING/LIVE, BMS 값, Fail-safe, IDS, SecOC 로그를 표시하는 기본 화면

이 화면은 P1의 소스 기준선이다. Qt 6가 현재 macOS 호스트에 없어 실제 Qt 빌드와 화면 동작은 통과로 판정하지 않았다.

### 3.5 시험과 실행 보조

- [`ivi_platform/test/test_can_parser.cpp`](../../../../../ivi_platform/test/test_can_parser.cpp): ECU payload와 parser 경계
- [`ivi_platform/test/test_secoc_verifier.cpp`](../../../../../ivi_platform/test/test_secoc_verifier.cpp): 알려진 MAC, 변조, `+100`, `+101`, replay, `0xFFFFFFFF → 0`
- [`ivi_platform/test/test_vehicle_data_service.cpp`](../../../../../ivi_platform/test/test_vehicle_data_service.cpp): 인증 전 미게시, 실패 후 last-good 유지, 분리 counter, IDS 유지, observer 해제
- [`ivi_platform/scripts/check_qt_ivi_env.sh`](../../../../../ivi_platform/scripts/check_qt_ivi_env.sh): 로컬 빌드·Qt·SocketCAN 도구 점검
- [`ivi_platform/scripts/send_ivi_test_vectors.py`](../../../../../ivi_platform/scripts/send_ivi_test_vectors.py): 명시적 더미 키 또는 외부 키를 사용하는 인증 시험 벡터 송신
- [`ivi_platform/scripts/measure_latency.py`](../../../../../ivi_platform/scripts/measure_latency.py): 지연 표본의 평균·p95·p99·최대값 요약

## 5. 완료 판정과 남은 범위

P1의 선택 이관과 core 재현 빌드는 완료했다. 구현 과정에서 P2 항목 중 인증 후 게시, counter wrap/replay, BMS·Fail-safe 상태 분리와 IDS 유지 기반도 먼저 반영했지만 P2 전체 완료로 보지 않는다.

다음 항목은 아직 남아 있다.

- P2: pending timeout·새 원본 덮어쓰기 정책, SocketCAN 오류 재시도, DLC와 교차 순서 전체 시험
- P3: 300ms stale 전환, sensorState, IDS 확인·재발생, CRITICAL/SHUTDOWN 전체 화면 경고, Qt 시험
- P4: Linux `vcan0` 자동 시나리오와 T1~T4 실제 계측
- P5: RPi4 배포, 물리 `can0`, Node A 통합과 복구 시험
- P6: Linux/Qt CI, 공식 TC 증거, 배포·데모·Release 문서

P1~P6의 최신 상태 원본은 상위 [aidlc-state.md](../aidlc-state.md)에서 계속 갱신한다.
