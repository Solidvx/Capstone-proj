## 1. 목적과 완료 범위

P4는 Linux 커널의 실제 SocketCAN 경로를 검증하고, 원본 CAN 수신부터 Qt Quick frame 제출까지 같은 단조 시계로 계측하는 단계다.

- `vcan0` 생성·정리와 Linux Release 빌드·CTest 자동화
- PF_CAN filter, DLC 8, SFF/RTR 경계와 wake pipe 종료 검증
- 실제 `vcan0`을 통한 정상 SecOC 게시, 변조 MAC, replay, pending timeout 검증
- T1 원본 수신, T2 Service 게시, T3 ViewModel 반영, T4 `frameSwapped` 계측
- `run_id,boot_id,sample_id,stage,timestamp_ns` 원시 CSV와 구간별 통계 생성
- 100ms BMS 주기 1,000표본에서 누락 수와 평균·p95·p99·최대 기록

실행 환경은 Apple Silicon 위 Lima Ubuntu 26.04 LTS VM이다. Linux 커널 SocketCAN과 Qt 6 offscreen scene graph는 실제 실행했지만 RPi4, MCP2515, 물리 `can0`, HDMI display는 P5 범위다.

## 2. 구현 결과

### 2.1 SocketCAN 통합

`SocketCanReceiver` callback에 `steady_clock::time_point`를 추가해 `read()` 직후 시각을 T1으로 전달한다. Linux 통합시험은 별도 PF_CAN 송신 소켓을 사용해 허용 프레임 1건만 callback으로 전달되는지, 미등록 ID·DLC 7·RTR가 차단되는지, `stop()`이 200ms 안에 끝나는지 확인한다.

같은 시험에서 receiver를 `VehicleDataService`에 연결해 정상 원본/auth가 한 번만 게시되는지 확인한다. 이후 변조 MAC, 같은 counter replay, 100ms 초과 auth를 실제 `vcan0`에 주입하고 measurement sequence와 last-good SOC가 바뀌지 않는지 확인한다.

### 2.2 T1~T4 계측

| 지점 | 코드 위치 | 의미 |
|---|---|---|
| T1 | `SocketCanReceiver::receiveLoop()` | 원본 CAN frame의 `read()` 직후 |
| T2 | `VehicleDataService::processAuth()` | 인증 성공 snapshot 게시 시각 |
| T3 | `DashboardViewModel::updateSnapshot()` | GUI thread property 교체 직후 |
| T4 | `QQuickWindow::frameSwapped` | 변경을 포함한 Qt Quick frame 제출 완료 |

sample sequence와 시각은 Node B 내부 상태로만 전달한다. CAN payload와 ICD wire 계약에는 측정 필드를 추가하지 않았다. `frameSwapped` 처리 중 직접 종료할 때 Qt Release에서 종료 재진입 충돌이 확인되어, 종료 요청을 다음 event-loop tick으로 넘겼다.

### 2.3 자동화와 통계

- `run_vcan_integration.sh`: Linux 확인, `vcan0` 준비, Werror Release core 빌드와 CTest
- `run_vcan_latency.sh`: 임시 더미 키, 대시보드, 100ms 인증 BMS 송신, 1,000표본 수집·요약
- `send_ivi_test_vectors.py`: 반복 횟수·간격과 증가 counter 지원
- `measure_latency.py`: T1~T4 완전 표본만 묶고 중복·역행·누락을 실패 처리

## 4. 판정

Linux Qt Release 전체 시험은 9/9 통과했다. 실제 `vcan0` 공식 1,000표본은 누락 0이며 T1→T4 평균 6.037ms, p99 8.028ms, 최대 10.827ms로 P4 환경의 목표 평균 50ms 이하·최대 100ms 이하를 충족했다.

20ms 과부하 사전 실행도 누락은 없고 평균·p99는 충족했으나 VM scheduling 정지로 최대 263.512ms가 발생했다. 이 결과를 공식 100ms 실행으로 대체하거나 숨기지 않고 시험 증거에 함께 기록했다.
