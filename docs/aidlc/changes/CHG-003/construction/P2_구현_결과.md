## 1. P2의 목적과 완료 범위

P2는 보호 CAN 원본과 인증 프레임의 결합 정책을 명시하고, 인증 실패·순서 역전·교체·만료에서 last-good과 counter가 오염되지 않도록 CAN·SecOC 핵심 경계를 완성하는 단계다. CAN ID, DLC, payload와 HMAC 입력 순서는 `docs/ICD.md`를 변경하지 않았다.

이번 구현은 다음 범위를 완료했다.

- BMS와 Fail-safe의 pending 원본·counter 상태 분리
- 인증 성공 뒤에만 snapshot과 counter commit
- 최초 정상 MAC, `+1`, `+100`, `+101`, replay, uint32 wrap과 변조 MAC 판정
- pending 만료, 같은 ID의 새 원본 교체, orphan auth와 두 인증 쌍의 교차 도착 정책
- Classic CAN DLC 8, SFF, 허용 ID, RTR·ERR·EFF 거부의 플랫폼 독립 검사
- SocketCAN 일시 수신 오류의 제한 재시도와 지속 오류 종료
- SecOC 연속 실패 횟수와 WARNING/CRITICAL 단계 기록

Linux `vcan0`에서 실제 syscalls와 프레임을 주입하는 시험은 P4 통합 범위로 남겼다. P2에서는 플랫폼 독립 정책 시험과 macOS core 빌드로 검증했다.

## 2. 확정한 pending 정책

공동 규약의 승인된 Q4=A에 따라 다중 후보 큐와 인증 선도착 보관은 추가하지 않았다.

| 상황 | 구현 동작 |
|---|---|
| 원본 수신 | 데이터 ID별 pending 슬롯 하나에 원본 8바이트와 monotonic 수신 시각 저장 |
| 같은 ID 새 원본 | 이전 미인증 원본을 폐기하고 최신 원본으로 교체, 교체 횟수 기록 |
| 다른 ID 원본 | BMS와 Fail-safe 슬롯이 독립이므로 서로 교체하지 않음 |
| 인증 선도착·원본 없음 | 다음 원본에 붙이지 않고 orphan auth로 즉시 거부 |
| pending 보관 시간 | 100ms. 이 값은 내부 pair 자원 정책이며 ICD의 BMS 300ms stale 판정을 변경하지 않음 |
| 100ms 경계 | 원본 수신 뒤 100ms 이상이면 만료·폐기하고 last-good 유지 |
| MAC·counter 실패 | pending, last-good, 마지막 성공 counter를 갱신하지 않음 |
| 인증 성공 | 해당 pending을 소비하고 counter와 snapshot을 한 번만 commit |

## 3. 구현 결과물

### 3.1 프레임 경계

- [`ivi_platform/hal/can_frame_validator.h`](../../../../../ivi_platform/hal/can_frame_validator.h)
- [`ivi_platform/hal/can_frame_validator.cpp`](../../../../../ivi_platform/hal/can_frame_validator.cpp)
- [`ivi_platform/test/test_can_frame_validator.cpp`](../../../../../ivi_platform/test/test_can_frame_validator.cpp)

Linux 헤더에 의존하지 않는 CAN frame validator를 추가했다. 다섯 허용 ID, DLC 8, SFF만 통과시키고 미등록 ID, DLC 오류, RTR, ERR, EFF와 SFF 범위를 벗어난 ID를 구분해 거부한다. `SocketCanReceiver`도 같은 validator를 사용하므로 시험과 실제 수신 경계가 갈라지지 않는다.

### 3.2 pending·SecOC 상태 처리

- [`ivi_platform/service/vehicle_data_service.h`](../../../../../ivi_platform/service/vehicle_data_service.h)
- [`ivi_platform/service/vehicle_data_service.cpp`](../../../../../ivi_platform/service/vehicle_data_service.cpp)
- [`ivi_platform/test/test_vehicle_data_service_security.cpp`](../../../../../ivi_platform/test/test_vehicle_data_service_security.cpp)

`VehicleDataService`에 100ms 만료, 최신 원본 교체, orphan auth 폐기와 진단 counter를 추가했다. BMS와 Fail-safe가 섞여 도착해도 독립 슬롯과 counter로 검증한다. 만료·변조·counter 거부 뒤에도 마지막 정상값을 보존한다.

누적 실패 외에 연속 실패 횟수를 관리한다. 인증 성공 시 연속 횟수를 0으로 복구하며 ICD §2.5.2에 맞춰 4회부터 WARNING, 10회부터 CRITICAL 메시지를 기록한다. 이 단계화는 내부 진단이며 IDS `0x200` 계약을 바꾸지 않는다.

### 3.3 SocketCAN 수신 복구

- [`ivi_platform/hal/receive_retry_policy.h`](../../../../../ivi_platform/hal/receive_retry_policy.h)
- [`ivi_platform/hal/socketcan_receiver.cpp`](../../../../../ivi_platform/hal/socketcan_receiver.cpp)
- [`ivi_platform/test/test_receive_retry_policy.cpp`](../../../../../ivi_platform/test/test_receive_retry_policy.cpp)

CAN 소켓을 non-blocking으로 열고 poll/read의 일시 오류는 10ms, 20ms, 30ms backoff로 최대 3회 재시도한다. 정상 read가 발생하면 예산을 초기화하고, 예산을 넘긴 지속 오류는 오류 문자열을 남기고 수신 loop를 종료한다. 종료 wake pipe와 worker join 동작은 유지했다.

### 3.4 기존 경계시험 보강

- `test_can_parser.cpp`: signed current 최솟값과 temperature `-40°C` offset
- `test_secoc_verifier.cpp`: 명시적 `+1` 허용과 동일 counter replay 거부
- `test_vehicle_data_service.cpp`: BMS 갱신이 마지막 Fail-safe 상태를 추론·초기화하지 않음
- `test_vehicle_data_service_security.cpp`: 99ms 허용/100ms 만료, last-good 유지, orphan, 교체, 교차 쌍, 실패 단계와 정상 복구

## 5. 남은 범위

- P5: RPi4 `can0`과 Node A 물리 통합
- P6: Linux/Qt CI, 공식 TC 증거와 배포·데모 문서

P1~P6의 최신 상태 원본은 상위 [aidlc-state.md](../aidlc-state.md)에서 관리한다.
