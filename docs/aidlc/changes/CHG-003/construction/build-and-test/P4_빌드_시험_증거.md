> 실행일: 2026-09-23
> 브랜치: `feat/ivi-vcan-integration`
> VM: Lima 2.2.0, Ubuntu 26.04 LTS, Linux 7.0.0-28-generic aarch64
> 컴파일러: GCC 15.2.0
> CMake: 4.2.3
> Qt: 6.10.2

## Linux SocketCAN 시험

```bash
./ivi_platform/scripts/run_vcan_integration.sh /tmp/ivi-p4-linux-core
```

`-Wall -Wextra -Wpedantic -Werror` Release 빌드 후 core 7종과 `test_socketcan_receiver`가 8/8 통과했다. 실제 PF_CAN socket과 `vcan0`에서 다음을 확인했다.

- 허용 SFF/DLC 8 수신, 미등록 ID·DLC 7·RTR 차단
- wake pipe를 통한 200ms 이내 worker 종료
- 정상 `0x100→0x102` 인증 게시와 T1/T2 sequence 생성
- 변조 MAC·counter replay·100ms timeout에서 last-good/sequence 보존
- 시험 종료 시 `RX/TX errors=0`, `dropped=0`

Qt target을 포함한 최종 Release build에서는 `vcan0`를 유지한 채 CTest 9/9가 0.25초에 통과했다.

`-fsanitize=address,undefined -fno-omit-frame-pointer`를 적용한 Linux core/vcan 구성도 8/8이 0.28초에 통과했고 leak·address·undefined behavior 오류가 없었다.

## 과부하 사전 실행

초기 스크립트의 20ms 간격 1,000표본은 T1→T4 평균 6.027ms, p99 8.512ms, 최대 263.512ms, 누락 0이었다. 최대값은 목표를 초과했고 같은 표본의 T2→T3가 243.838ms여서 VM scheduling 정지의 영향을 확인했다. BMS 계약 주기와 다른 입력이므로 공식 결과로 사용하지 않았으며 원시 SHA-256은 `cc2e5f389d06f26aa649706ace28e2e733d6224079e08b89a08d32e10ab2845d`다.
