# IVI Plan B P3 구현 결과

> 작업 ID: CHG-003
> 구현일: 2026-09-23
> 작업 브랜치: `feat/ivi-qt-dashboard`
> 선행 기준: P2 최신 커밋 `38d96d6`

## 1. P3 목적과 완료 범위

P3는 인증된 서비스 snapshot을 Qt Quick 화면에 안전하게 연결하고, 초기 대기·stale·Fail-safe·IDS 상태를 운전자가 구분할 수 있게 만드는 단계다. 이번 구현은 P2에서 미검증이던 실제 Qt 6 앱 빌드까지 함께 완료했다.

- 마지막 인증 성공 BMS 시각 기준 300ms stale 전환
- stale 이후 마지막 정상 수치와 경과시간 보존
- Fail-safe 수신이 BMS stale 기준 시각을 갱신하지 않도록 상태 분리
- IDS 경보의 사용자 확인과 새 경보 경쟁 방지
- `AttackType=0` 프레임이 사용자 확인을 대신하지 못하도록 유지
- GUI thread queued 갱신과 snapshot 단위 property 교체
- 초기값 `--`, LIVE/WAITING/STALE, sensor 상태, SOC 단계 색상 표시
- CRITICAL/SHUTDOWN 전체 화면 overlay와 reason `0x07` 문자열 표시
- CAN·키 없이 8개 UI 상태를 재현하는 demo 모드와 임시 screenshot 출력

Linux SocketCAN 실제 syscall과 `vcan0` 주입은 P4 범위이므로 P3 완료로 확대하지 않는다.

## 2. 상태 처리 결과

### 2.1 stale와 last-good

`VehicleDataService::refreshTime()`을 추가하고 Qt 앱의 50ms timer에서 호출한다. BMS 인증 성공 시각부터 300ms가 되면 `stale=true`로 바뀌며 SOC·SOH·전압·전류·온도는 마지막 정상값을 유지한다. Fail-safe 인증이나 IDS 이벤트는 이 시각을 갱신하지 않는다.

### 2.2 IDS 확인 경쟁

각 새 IDS 경보에 증가하는 sequence를 부여한다. QML의 확인 버튼은 화면에서 관찰한 sequence를 서비스에 전달하며, 그 사이 새 경보가 도착해 sequence가 달라졌다면 확인 요청을 거부한다. 따라서 오래된 클릭이 새 경보를 지우지 않는다. 확인은 stale, sensor 상태, Fail-safe 상태를 변경하지 않는다.

### 2.3 sensorState 경계

ICD §8의 sensorState byte 7은 승인된 다음 전환 목표이며 아직 현행 wire 계약이 아니다. P3는 `VehicleData`와 UI에서 코드 0~6의 표시 상태를 준비했지만, 현행 `0x100` byte 7은 계속 reserved `0x00`으로 검증한다. 화면에는 코드 0을 `UNSUPPORTED_LEGACY_WIRE`로 표시하며 정상 sensor 상태로 오인하지 않는다. 실제 wire 활성화는 ECU·IVI·Python 벡터·시험을 함께 바꾸는 별도 인터페이스 변경이다.

## 4. 재현 가능한 화면

`ivi_dashboard`는 CAN 장치와 키 없이 다음 demo 상태를 실행할 수 있다.

```bash
./ivi_dashboard --demo waiting
./ivi_dashboard --demo normal
./ivi_dashboard --demo stale
./ivi_dashboard --demo sensor-error
./ivi_dashboard --demo warning
./ivi_dashboard --demo critical
./ivi_dashboard --demo shutdown
./ivi_dashboard --demo ids
```

`--demo-screenshot <png>`와 `--demo-exit-ms <ms>`는 자동 화면 로드·렌더 확인에 사용한다. 생성 PNG는 시험 임시 산출물이므로 저장소에는 추가하지 않았다.

## 5. 검증 결과

| 검증 | 결과 |
|---|---|
| Qt 6.11.2 Debug + Werror | 앱 빌드 성공, CTest 8/8 통과, 3.14초 |
| Qt 6.11.2 Release + Werror | 앱 빌드 성공, CTest 8/8 통과, 2.89초 |
| ASan + UBSan core | CTest 7/7 통과, 2.89초 |
| 8개 offscreen demo | 모두 QML 로드·렌더·정상 종료 |
| T2→T3 host 측정 | Release 100표본, 평균 0.0194079ms, p99 0.030958ms |

T2→T3 값은 macOS 호스트에서 worker 호출부터 ViewModel property signal까지 측정한 결과다. CAN 수신, QML scene graph 렌더, 물리 화면 반영은 포함하지 않으며 P4/P5 계측을 대신하지 않는다. 명령과 환경은 [P3 빌드·시험 증거](build-and-test/P3_빌드_시험_증거.md)에 기록했다.

## 6. 남은 범위

- P4: Ubuntu/Linux `vcan0`, 실제 SocketCAN filter·poll/read·종료와 T1~T4 계측
- sensorState wire 활성화: ICD §8 절차에 따른 Node A·Node B 동시 전환
- P5: RPi4 `can0`, Node A 물리 통합과 화면 증거
- P6: Linux Qt CI, 배포·운영·최종 공식 TC 문서
