# 전체 구조 골격 적용

사용자의 후속 요청에 따라 프로젝트구조개선.md §4의 고정 경로를 모두 배치하고 가변 경로를 템플릿으로 구체화했다. 이전 개선안·운영 안내·검증 기록의 “미생성/실제 작업 때 생성”은 이전 배치 방침이다. 이번에는 골격을 먼저 배치하되 실질적인 작업·실행 결과는 나중에 기록한다. 기존 파일 본문은 수정하지 않았다.

| 계획 표기 | 실제 경로 | 의미 |
|---|---|---|
| CHG-<번호> | docs/aidlc/changes/CHG-template/ | 실제 작업 ID가 아닌 복사용 템플릿 |
| <작업단위> | construction/unit-template/ | 실제 단위명으로 바꿔 사용할 골격 |
| tools/workflow/ | 동일 경로 | 미구현 Python 골격과 도구 시험 안내 |
| .claude/settings.json | 동일 경로 | 빈 객체. 표준 JSON 주석 대신 .claude/README.md에 목적 기재 |
| .codex/config.toml | 동일 경로 | 주석만 존재. MCP 연결 미등록 |
| ivi_platform/ | 동일 경로 | 목적 안내만 있는 제품 경계; IVI 구현 없음 |

Windows 파일명에 사용할 수 없는 꺾쇠는 문자 그대로 생성하지 않았다. ICD.md, SRS.md, SDD-*.md 등의 묶음 표기는 기존 실제 파일로 충족한다. 기존 파일에는 주석을 일괄 삽입하지 않았다. 각 신규 Markdown에는 목적 주석과 읽을 수 있는 안내, Python/TOML에는 주석을 넣었다. 목적 README는 빈 디렉터리를 형상 관리할 수 있도록 한다.

협업 시 공통 기준 커밋에서 분기하고, 실제 작업 ID와 수정 담당을 정한다. 현재 Git 메타데이터는 없으며 이 작업은 저장소 초기화·브랜치 생성·병합을 수행하지 않는다. 골격 배치가 향후 병합 충돌이나 제품 호환성을 보장하지 않는다.

검증 결과는 이번 작업의 [scope-verification.json](scope-verification.json)을 따른다. 최초 baseline은 이전 구조 적용 기록으로 보존한다. [scaffold-paths.json](scaffold-paths.json)은 이번 선배치 단계의 부분 목록이며, 이후 추가·참조 정정을 포함한 현재 전체 목록은 [path-map.csv](path-map.csv), 역할·의존성 진입점은 [document-map.md](document-map.md)이다. 실행 도구·hook·MCP·제품 기능의 구현 완료는 아니다.

구조도에서 추출한 고정·템플릿 경로 73개 모두 존재한다. 이번 신규 파일은 골격·안내 30개와 검증·목록 JSON 2개, 총 32개다. 기존 159개 중 157개는 바이트 동일하며 루트 README와 AIdlc README는 새 적용 기록으로 가는 링크만 추가했다. Python 골격 3개는 구문 검사와 직접 실행 시 미구현 실패 종료를 확인했다. JSON/TOML은 빈 설정으로 파싱된다. 제품 기능과 자동화 연결은 여전히 미구현이다.
